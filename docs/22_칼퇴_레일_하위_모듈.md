# 칼퇴 레일 구조 개편에 맞추기: 하위 모듈 켜고 끄기, 설정만 열기, SHA 장부 (2026-11-22)

칼퇴 레일이 바뀌었다(칼퇴 `docs/10_모듈_규격과_장부.md` 1장, v0.1.185). 맨 위 [칼퇴]는 매니저(모듈 관리·설정·로그)만 맡고, 훈수꾼은 자기 레일 탭을 가진다. 칼퇴 [모듈 관리]와 훈수꾼 소개 화면에서 훈수꾼 전체와 **하위 모듈**을 켜고 끈다. 끈 하위 모듈은 **아예 불러오지 않는다**(가볍게 하려는 것). 받은 쪽지: claude-workspace `bridge/inbox-hunsu/2026-11-22-001-rail-restructure-todo.md`. 판 0.0.236.

## 1. 하위 모듈 = 훈수꾼 모듈 하나하나
- 칼퇴가 켜고 끄는 하위 모듈은 `modules\<id>\`의 훈수꾼 모듈 하나와 같다. **id는 모듈 id 그대로**(`hunsu-selection` 같은 모양, 칼퇴 규격 영문·숫자·-·_에 맞음). 바꿔 부르는 표를 두지 않는다(같은 것을 두 번 적지 않기).
- 이름·설명도 모듈 선언에서 온다: `name` = 모듈 `name`, `summary` = 모듈 `description`의 **첫 문장**. `tools/pack_app.ps1`이 포장할 때 `hunsu.app.json`의 `modules`를 만든다(순서는 모듈 `order`). 모듈 이름·설명을 고치면 다음 묶음에 저절로 따라간다.
- `default`는 모두 `true`. 칼퇴의 켜고 끄기는 "불러오기"이고, 훈수꾼 설정 창 [모듈]의 켜고 끄기는 "보이기"로 따로다(처음 보이는 것은 지금처럼 선택 요약·색연필 수식 흐름, `enabledByDefault`). 불러오기까지 기본으로 끄면 판을 올렸을 때 쓰던 모듈이 말없이 사라질 수 있어 모두 켜 둔다.
- 칼퇴 시안의 "선택 요약"은 `hunsu-selection`, "점검 결과"에 가까운 것은 `hunsu-audit`(책 점검)이다. 확정 목록 26개는 2장 표.

## 3. 켜진 하위 모듈만 불러오기
- 시작할 때 환경변수 `CLOCKOUT_MODULES_FILE`이 가리키는 `modules.enabled.json`(`{"spec":0,"enabled":[…]}`)을 읽는다(`Shell/ModuleGateFile.cs`, 판단은 `Core/Manifest/ModuleGate.cs`).
- `enabled`에 없는 모듈은 **선언 파일도 읽지 않고** 건너뛴다(`ModuleCatalog`, 기록 `module_skip`). 화면·조회·핀 창 모두 없다.
- 환경변수·파일이 없거나, 64KB를 넘거나, JSON이 깨졌거나, `spec`이 0이 아니거나, `enabled`가 글자 배열이 아니면 → 묶음 선언(`exe` 한 칸 위 `hunsu.app.json`)의 `default`를 따른다. 선언도 없으면(개발 실행) 모두 불러온다. 어느 쪽이었는지는 기록 `module_gate`(source = clockout | default | all, problem).
- 선언에 없는 모듈(사용자가 모듈 폴더에 직접 넣은 것)은 칼퇴가 모르는 모듈이라 늘 불러온다.
- 설정 창 [모듈] 머리글에 "칼퇴에서 끈 N개는 불러오지 않음"이 보인다.

## 4. 반영 시점 (결정: 껐다 켜면 반영)
- 켜져 있는 동안 칼퇴에서 바꾼 선택은 **훈수꾼을 껐다 켜면 반영**한다. 파일 감시로 즉시 반영하지 않는다.
- 이유: 모듈 하나를 실행 중에 빼려면 도크·핀 창·묶음·사이드바 탭·셀 위 표시·조회 구독을 모두 풀어야 하고, 더하려면 그 반대를 해야 한다. 고장 날 곳이 많은데 얻는 것은 껐다 켜는 1~2초뿐이다. 나중에 필요하면 다시 정한다.
- 칼퇴 쪽에 부탁(쪽지): 스위치를 바꾸면 "훈수꾼을 다시 켜면 반영돼요" 안내와 함께 [지금 다시 켜기](= `quitMessage` 보낸 뒤 다시 실행)를 두면 편하다.

## 5. 설정창만 열기 (`settingsArgs: ["--settings"]`)
- 꺼진 훈수꾼을 `ClockOut.Hunsu.exe --settings`로 켜면 **설정 창 하나만** 뜬다("설정만" 모드, `Shell/ShellController.SettingsOnly.cs`). 도크·핀 창·사이드바·알림 영역 아이콘을 띄우지 않고 엑셀을 따라가거나 묻지 않는다. 창을 닫으면 끝난다.
- 바꾼 설정·켜짐·자리는 저장되어 다음에 켤 때 그대로 쓴다(설정 창에 안내 한 줄).
- 설정만 띄운 사이 칼퇴 [켜기](보통 실행)를 누르면, 새로 켠 쪽이 잠금에 걸려 켜진 쪽에 `ClockOut.App.Start`를 보내고 끝나고, 켜진 쪽이 **이어서 훈수꾼을 켠다**(설정 창은 열린 채). 설정 창의 [훈수꾼 켜기] 단추나 Ctrl+Alt+H도 같다.
- 이미 켜져 있을 때 `--settings`는 0.0.226 그대로: 켜진 쪽에 `ClockOut.App.Settings`를 넘겨 설정 창을 연다.
- 설정만 모드에서도 `CLOCKOUT_MODULES_FILE`을 읽는다(칼퇴가 같이 넘긴다고 했다). 끈 모듈은 설정 창 [모듈]에도 안 나온다.

## 7. SHA-256 장부
- 장부: `releases/hunsu_sha256.md`(판·날짜·SHA·크기·태그, 최신이 위). 지난 판 0.0.045·0.0.201·0.0.202는 카탈로그 기록에서 옮겼다.
- `pack_app.ps1`은 `release-record.json`(장부 한 줄 `ledgerRow` 포함)을 만들고, 장부에 같은 판이 **다른 SHA로** 있으면 실패한다(한 판 = 한 SHA).
- 순서(docs/21에 더함): 묶음 → Release 올리기 → Release 파일을 받아 SHA 다시 계산해 맞춰 보기 → 카탈로그 `sha256`과 장부 한 줄을 같은 값으로. 서버 비공개 장부도 이 값을 쓴다.
