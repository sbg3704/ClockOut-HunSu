# 칼퇴 레일 구조 개편에 맞추기: 하위 모듈 켜고 끄기, 설정만 열기, SHA 장부 (2026-11-22)

칼퇴 레일이 바뀌었다(칼퇴 `docs/10_모듈_규격과_장부.md` 1장, v0.1.185). 맨 위 [칼퇴]는 매니저(모듈 관리·설정·로그)만 맡고, 훈수꾼은 자기 레일 탭을 가진다. 칼퇴 [모듈 관리]와 훈수꾼 소개 화면에서 훈수꾼 전체와 **하위 모듈**을 켜고 끈다. 끈 하위 모듈은 **아예 불러오지 않는다**(가볍게 하려는 것). 받은 쪽지: claude-workspace `bridge/inbox-hunsu/2026-11-22-001-rail-restructure-todo.md`. 판 0.0.236.

## 1. 하위 모듈 = 훈수꾼 모듈 하나하나
- 칼퇴가 켜고 끄는 하위 모듈은 `modules\<id>\`의 훈수꾼 모듈 하나와 같다. **id는 모듈 id 그대로**(`hunsu-selection` 같은 모양, 칼퇴 규격 영문·숫자·-·_에 맞음). 바꿔 부르는 표를 두지 않는다(같은 것을 두 번 적지 않기).
- 이름·설명도 모듈 선언에서 온다: `name` = 모듈 `name`, `summary` = 모듈 `description`의 **첫 문장**. `tools/pack_app.ps1`이 포장할 때 `hunsu.app.json`의 `modules`를 만든다(순서는 모듈 `order`). 모듈 이름·설명을 고치면 다음 묶음에 저절로 따라간다.
- `default`는 모두 `true`. 칼퇴의 켜고 끄기는 "불러오기"이고, 훈수꾼 설정 창 [모듈]의 켜고 끄기는 "보이기"로 따로다(처음 보이는 것은 지금처럼 선택 요약·색연필 수식 흐름, `enabledByDefault`). 불러오기까지 기본으로 끄면 판을 올렸을 때 쓰던 모듈이 말없이 사라질 수 있어 모두 켜 둔다.
- 칼퇴 시안의 "선택 요약"은 `hunsu-selection`, "점검 결과"에 가까운 것은 `hunsu-audit`(책 점검)이다. 확정 목록 27개는 2장 표(2026-11-22 한 수 더함).

## 3. 켜진 하위 모듈만 불러오기
- 시작할 때 환경변수 `CLOCKOUT_MODULES_FILE`이 가리키는 `modules.enabled.json`(`{"spec":0,"enabled":[…]}`)을 읽는다(`Shell/ModuleGateFile.cs`, 판단은 `Core/Manifest/ModuleGate.cs`).
- `enabled`에 없는 모듈은 **선언 파일도 읽지 않고** 건너뛴다(`ModuleCatalog`, 기록 `module_skip`). 화면·조회·핀 창 모두 없다.
- 환경변수·파일이 없거나, 64KB를 넘거나, JSON이 깨졌거나, `spec`이 0이 아니거나, `enabled`가 글자 배열이 아니면 → 묶음 선언(`exe` 한 칸 위 `hunsu.app.json`)의 `default`를 따른다. 선언도 없으면(개발 실행) 모두 불러온다. 어느 쪽이었는지는 기록 `module_gate`(source = clockout | default | all, problem).
- 선언에 없는 모듈(사용자가 모듈 폴더에 직접 넣은 것)은 칼퇴가 모르는 모듈이라 늘 불러온다.
- 설정 창 [모듈] 머리글에 "칼퇴에서 끈 N개는 불러오지 않음"이 보인다.

## 4. 반영 시점 (결정: 껐다 켜면 반영)
- 켜져 있는 동안 칼퇴에서 바꾼 선택은 **훈수꾼을 껐다 켜면 반영**한다. 파일 감시로 즉시 반영하지 않는다.
- 이유: 모듈 하나를 실행 중에 빼려면 도크·핀 창·묶음·사이드바 탭·셀 위 표시·조회 구독을 모두 풀어야 하고, 더하려면 그 반대를 해야 한다. 고장 날 곳이 많은데 얻는 것은 껐다 켜는 1~2초뿐이다. 나중에 필요하면 다시 정한다.
- 칼퇴 쪽에 부탁(쪽지): 스위치를 바꾸면 "훈수꾼을 다시 켜면 반영돼요" 안내와 함께 [지금 다시 켜기](= `quitMessage` 보낸 뒤 다시 실행)를 두면 편하다.

## 5. 설정창만 열기 (`settingsArgs: ["--settings"]`)
- 꺼진 훈수꾼을 `ClockOut.Hunsu.exe --settings`로 켜면 **설정 창 하나만** 뜬다("설정만" 모드, `Shell/ShellController.SettingsOnly.cs`). 도크·핀 창·사이드바·알림 영역 아이콘을 띄우지 않고 엑셀을 따라가거나 묻지 않는다. 창을 닫으면 끝난다.
- 바꾼 설정·켜짐·자리는 저장되어 다음에 켤 때 그대로 쓴다(설정 창에 안내 한 줄).
- 설정만 띄운 사이 칼퇴 [켜기](보통 실행)를 누르면, 새로 켠 쪽이 잠금에 걸려 켜진 쪽에 `ClockOut.App.Start`를 보내고 끝나고, 켜진 쪽이 **이어서 훈수꾼을 켠다**(설정 창은 열린 채). 설정 창의 [훈수꾼 켜기] 단추나 Ctrl+Alt+H도 같다.
- 이미 켜져 있을 때 `--settings`는 0.0.226 그대로: 켜진 쪽에 `ClockOut.App.Settings`를 넘겨 설정 창을 연다.
- 설정만 모드에서도 `CLOCKOUT_MODULES_FILE`을 읽는다(칼퇴가 같이 넘긴다고 했다). 끈 모듈은 설정 창 [모듈]에도 안 나온다.

## 7. SHA-256 장부
- 장부: `releases/hunsu_sha256.md`(판·날짜·SHA·크기·태그, 최신이 위). 지난 판 0.0.045·0.0.201·0.0.202는 카탈로그 기록에서 옮겼다.
- `pack_app.ps1`은 `release-record.json`(장부 한 줄 `ledgerRow` 포함)을 만들고, 장부에 같은 판이 **다른 SHA로** 있으면 실패한다(한 판 = 한 SHA).
- 순서(docs/21에 더함): 묶음 → Release 올리기 → Release 파일을 받아 SHA 다시 계산해 맞춰 보기 → 카탈로그 `sha256`과 장부 한 줄을 같은 값으로. 서버 비공개 장부도 이 값을 쓴다.

## 9. 칼퇴가 받아 둔 모듈 읽기 (2026-11-22, 0.0.266, 칼퇴 PR#59·docs/10 3장)
- 칼퇴가 카탈로그 `modules`에서 받은 모듈을 `<apps>\hunsu\modules\<모듈id>\<판>\`에 풀고(다 풀면 `.clockout-module` 표시 파일) 환경변수 **`CLOCKOUT_MODULES_DIR`**로 넘긴다. 훈수꾼은 시작할 때 이 폴더에서 모듈 id마다 표시 파일이 있는 **가장 높은 판 하나**를 읽는다(`Core/Manifest/ModuleSources`, `Shell/ModuleCatalog.Sources`). 안전하지 않은 id·판 이름은 건너뛴다.
- 받은 모듈도 선언형(`<id>.hunsu.json`, `view.json`)이라 코드를 실행하지 않는다. 같은 64KB 한도·검사를 거친다.
- 켜짐은 기존 문(`CLOCKOUT_MODULES_FILE`)을 그대로 쓴다. 칼퇴의 켜짐 목록에는 받은 모듈도 들어 있고(칼퇴 `AppServices.ModulesOf`), 단독 실행이면 선언에 없는 모듈이라 늘 불러온다(3장).
- **같은 id가 묶음 기본 모듈에도 있으면(결정, Claude 2026-11-22)**: 선언 `version`이 더 높은 쪽을 쓴다. 같거나 판을 못 읽으면 묶음 기본 모듈을 둔다(옛 판으로 되돌아가지 않게). 기록 `module_load`(from=bundled|downloaded)·`module_replace`·`module_keep`·`module_dir`.

## 10. 계기판 값 memoryMb·startMs (2026-11-22, 0.0.266)
- 칼퇴 계기판·"약 N MB" 배지는 선언의 `memoryMb`·`startMs`를 쓴다(켜져 있을 때는 칼퇴가 실제 메모리를 씀). **결정(Claude)**: 숫자를 지어내지 않는다. 훈수꾼이 준비될 때 기록(`--log`)에 `load` 줄(`startMs` = 프로세스 시작부터 준비까지, `memoryMb` = 작업 집합)을 남기고, PC에서 몇 번 잰 큰 값을 `assets/load.json`(`{"memoryMb": 숫자, "startMs": 숫자}`)에 적으면 `pack_app.ps1`이 선언에 넣는다. 파일이 없으면 칸을 비운다(칼퇴는 "—").
- 모듈별 `memoryMb`·`startMs`는 넣지 않는다. 선언형 모듈 하나는 따로 잴 만큼 크지 않고, 지어낸 값이 되기 쉽다.
- 칼퇴 `settings`(`CLOCKOUT_SETTINGS_FILE`)·`settings[].module`은 해당 없음: 훈수꾼은 `settingsArgs`로 자체 설정 창을 쓰고, 그러면 칼퇴가 설정 칸을 그리지 않는다.


## 11. 모듈 계약 규격 (2026-11-22, 0.0.267, 칼퇴 docs/11·쪽지 inbox-hunsu/2026-11-22-004)
- 사용자 결정(칼퇴): 칼퇴 화면이 바뀌어도 훈수꾼을 고치지 않게 한다. 선언에는 하위 모듈·켜기/끄기·사용법·패치노트·설정 연결 명령만 두고 화면 모양 칸은 넣지 않는다.
- `pack_app.ps1`이 선언 맨 위에 `contract_version: 1`, 설정창 인자를 `commands.settings: ["--settings"]`로 넣는다. 옛 칼퇴를 위해 `settingsArgs`도 남긴다(둘 다 있으면 칼퇴는 commands 우선).
- 읽는 쪽: `ModuleGate`는 `spec`·`enabled`·`modules[].id/default`만 보고 나머지 칸은 무시한다(시험 `UnknownFields_AreIgnored`). `settings.values.json`은 읽지 않는다.
- 칼퇴에 새 기능이 필요하면 선언에 칸을 만들지 말고 `bridge/inbox-clockout/`로 요청한다.

## 12. 칼퇴 소개 화면 탭·버튼 (2026-11-22, 0.0.277, 칼퇴 docs/11 4·5장, 쪽지 inbox-hunsu/2026-11-22-005)
- 사용자 결정(칼퇴): 붙는 쪽이 디자인 기준 안에서 탭·버튼을 스스로 정한다. 모양(색·글꼴·크기)은 칼퇴가 그린다.
- 선언 `contract_version: 2`. 탭 순서: [하위 모듈] → **[훈수꾼 설정]**(kind buttons) → [사용법] → [패치노트] → 적지 않은 기본 탭(찾기·팩·라이브러리)은 칼퇴 기본 순서로 뒤에.
- [훈수꾼 설정] 단추(결정, Claude): 「처음이라면」 설정 마법사(강조), 「바로 가기」 모듈 보이기·순서 / 모양 바꾸기 / 모듈 옵션 / 프로필 / 일반 설정. 명령 `commands.actions`는 `--settings <쪽>`이다.
- `--settings <쪽>`(Core/SettingsPages: general·modules·look·options·profiles·wizard, 번호는 뒤에만 더함). 이미 켜져 있으면 `ClockOut.App.Settings`의 wParam에 쪽 번호를 실어 넘긴다(0 = general, 옛 칼퇴와 같음). 꺼져 있으면 설정만 모드로 그 쪽(마법사면 마법사)만 뜨고, 마지막 창을 닫으면 끝난다.
- 디자인 토큰(`CLOCKOUT_THEME_FILE`)은 지금 쓰지 않는다(결정, Claude): 칼퇴 규격의 의무는 kind window(자기 창 탭)에 걸리고, 훈수꾼 설정 창·패널 모양은 훈수꾼 룩·테마(docs/09, 사용자 결정)를 따른다. 칼퇴와 맞출지는 사용자에게 물을 후보(docs/20).
