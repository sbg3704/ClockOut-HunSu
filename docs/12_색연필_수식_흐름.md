# 색연필 수식 흐름 (2026-11-16)

사용자 요청(2026-11-16): "수식흐름이 손글씨 형태의 색연필 느낌으로 셀 화면들 위에 휙휙휙 그려지면 너무 좋을 것 같아."
새 기능의 선택은 Claude 추천대로 가라는 사용자 지시(2026-11-16)에 따라 아래를 골랐다. 바꾸고 싶으면 "바꾸는 곳"만 고친다.

## 1. 무엇을 했나
- 모듈 `hunsu-pencilflow`(색연필 수식 흐름, 선언만, 기본 꺼짐). 조회는 기존 `mark`(다리 0.0.014)를 그대로 쓴다: **다리(VBA)를 바꾸지 않았다.**
- 표시층 선언에 `style: "pencil"` + `role`(`active` 고른 칸 / `pre` 쓰는 칸 / `dep` 쓰이는 칸)을 더했다(`MarkSpec.Role`). 칸 자리에 `addr`가 있어야 한다.
- 그리기: 고른 칸을 주황으로 빙 두르고, 이웃 칸은 비스듬히 칠하고 둘러싼 뒤, 쓰는 칸 → 고른 칸, 고른 칸 → 쓰이는 칸으로 휘어진 손 화살표(V 화살촉)를 긋는다. 칸 위에 손글씨 이름표.
- 움직임("휙휙휙"): 획마다 시작 시각을 정해 앞 획이 끝나기 전에 다음 획이 시작되게 겹쳐 이어 그린다(전체 1.1초 안). 점선을 밀어 처음에서 끝으로 그려지게 하고, 처음이 빠르고 끝에서 멈칫하는 곡선(`PowerEase` 2.5, 아웃)을 쓴다.

### 1-1. 추가(2026-11-16, 사용자 요청: "형태를 다양하게 주고 번호도 작게 붙여서 하나하나 쫓아갈 수 있게, 가시화가 중요")
- **프로필(모양)**: 고른 칸은 두 겹 주황 고리, 쓰는 칸은 네모(범위면 대괄호 `[ ]`), 쓰이는 칸은 동그라미(범위면 동그라미 + 물결 밑줄). 모양만 봐도 앞/뒤, 한 칸/범위가 구별된다. 범위 판정은 고른 칸보다 가로·세로가 1.4배 넘는지.
- **번호**: 화살표 한가운데에 작은 동그라미 숫자. 쓰는 칸 → 쓰이는 칸 순으로 이어서 1, 2, 3…, 한 묶음 안은 읽는 순서(위→아래, 왼쪽→오른쪽). 그려지는 순서도 번호 순서.
- 아직 안 한 것: **여러 단계 흐름도**(쓰는 칸의 쓰는 칸까지 이어 따라가기). 지금 조회 `mark`는 바로 앞뒤 한 단계의 자리만 주므로, 여러 단계는 다리 조회를 늘려야 한다(`flow.graph`는 2단계까지 주지만 칸 자리가 없음). 다음 일 후보.
- 번호표·글꼴 크기는 `PencilPainter.Badge`, 모양 선택은 `FlowSketch.DrawProfile`.

## 4. 한계 (일부러 안 한 것, 못 본 것)
- 같은 시트의 **보이는 칸만**(조회 `mark`의 한계). 시트를 넘는 흐름은 `hunsu-flowgraph`(목록).
- 활성 칸 하나만 기준(여러 칸을 고른 경우 활성 칸).
- **화면으로 보지 못했다**: 클라우드에는 Windows·엑셀이 없다. 점·시간 계산은 시험으로, 모양은 SVG로 그려 눈으로 확인했지만 WPF 투명 창의 실제 움직임·결 무늬·글꼴 적용은 PC에서 눈으로 확인해야 한다.
- 투명(레이어드) 창은 프레임마다 합성 비용이 든다. 끊기면 `FlowSketch.MaxPerGroup`을 줄이거나 `SetDesiredFrameRate`를 20으로.
