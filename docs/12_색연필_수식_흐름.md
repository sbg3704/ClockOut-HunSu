# 색연필 수식 흐름 (2026-11-16)

사용자 요청(2026-11-16): "수식흐름이 손글씨 형태의 색연필 느낌으로 셀 화면들 위에 휙휙휙 그려지면 너무 좋을 것 같아."
새 기능의 선택은 Claude 추천대로 가라는 사용자 지시(2026-11-16)에 따라 아래를 골랐다. 바꾸고 싶으면 "바꾸는 곳"만 고친다.

## 1. 무엇을 했나
- 모듈 `hunsu-pencilflow`(색연필 수식 흐름, 선언만, 기본 꺼짐). 조회는 기존 `mark`(다리 0.0.014)를 그대로 쓴다: **다리(VBA)를 바꾸지 않았다.**
- 표시층 선언에 `style: "pencil"` + `role`(`active` 고른 칸 / `pre` 쓰는 칸 / `dep` 쓰이는 칸)을 더했다(`MarkSpec.Role`). 칸 자리에 `addr`가 있어야 한다.
- 그리기: 고른 칸을 주황으로 빙 두르고, 이웃 칸은 비스듬히 칠하고 둘러싼 뒤, 쓰는 칸 → 고른 칸, 고른 칸 → 쓰이는 칸으로 휘어진 손 화살표(V 화살촉)를 긋는다. 칸 위에 손글씨 이름표.
- 움직임("휙휙휙"): 획마다 시작 시각을 정해 앞 획이 끝나기 전에 다음 획이 시작되게 겹쳐 이어 그린다(전체 1.1초 안). 점선을 밀어 처음에서 끝으로 그려지게 하고, 처음이 빠르고 끝에서 멈칫하는 곡선(`PowerEase` 2.5, 아웃)을 쓴다.

### 1-1. 추가(2026-11-16, 사용자 요청: "형태를 다양하게 주고 번호도 작게 붙여서 하나하나 쫓아갈 수 있게, 가시화가 중요")
- **프로필(모양)**: 고른 칸은 두 겹 주황 고리, 쓰는 칸은 네모(범위면 대괄호 `[ ]`), 쓰이는 칸은 동그라미(범위면 동그라미 + 물결 밑줄). 모양만 봐도 앞/뒤, 한 칸/범위가 구별된다. 범위 판정은 고른 칸보다 가로·세로가 1.4배 넘는지.
- **번호**: 화살표 한가운데에 작은 동그라미 숫자. 쓰는 칸 → 쓰이는 칸 순으로 이어서 1, 2, 3…, 한 묶음 안은 읽는 순서(위→아래, 왼쪽→오른쪽). 그려지는 순서도 번호 순서.
- 아직 안 한 것: **여러 단계 흐름도**(쓰는 칸의 쓰는 칸까지 이어 따라가기). 지금 조회 `mark`는 바로 앞뒤 한 단계의 자리만 주므로, 여러 단계는 다리 조회를 늘려야 한다(`flow.graph`는 2단계까지 주지만 칸 자리가 없음). 다음 일 후보.
- 번호표·글꼴 크기는 `PencilPainter.Badge`, 모양 선택은 `FlowSketch.DrawProfile`.

### 1-2. 시그니처 기능, 여러 단계, 보이는 형태 고르기 (2026-11-16, 사용자: "이건 훈수꾼 시그니처 기능이 될 거야", "형광 마커나 펜 색연필 전체적으로 수기 형태의 캘리그라피 느낌으로", 시안 보고 "완전 좋아")
- **시그니처로 둔다**: 처음 쓸 때부터 켜진다(`enabledByDefault`에 `hunsu-pencilflow`). 시안 그림은 프로젝트 파일 `hunsu-pencil/looks_pencil_marker_pen.png`.
- **여러 단계**: 다리 0.0.020의 조회 `mark`가 `pre2`(쓰는 칸의 쓰는 칸)·`dep2`(쓰이는 칸의 쓰이는 칸)를 더 준다. 줄마다 `to`(이어지는 첫 단계 칸 주소)가 있어 화살표를 이을 수 있다. 같은 시트의 보이는 칸만, 부모마다 6칸, 번호는 계산이 흘러가는 순서(더 앞 → 쓰는 칸 → 고른 칸 → 쓰이는 칸 → 더 뒤)로 1, 2, 3…이고 그려지는 순서도 같다. 두 번째 단계는 가늘고 옅다.
- **보이는 형태 3가지** (`Core/Marks/SketchLook.cs` 표에 한 줄 더하면 새 형태): 색연필(종이 결, 비스듬히 칠하기, 덧그림), 형광 마커(굵고 반투명, 넓게 칠함), 펜(가늘고 깔끔, 칠하지 않음). 설정 창 [일반]의 "수식 흐름 그림"에서 고르고 바로 반영된다(설정 `pencilLook`).
- **캘리그라피 강약**: 셋 다 획이 가늘게 시작해 굵어지고 끝은 날렵하게 빠지며(`Taper`), 납작한 펜촉처럼 방향에 따라 굵기가 달라진다(`Nib`). 그리는 쪽은 굵기가 점마다 다른 획을 짧은 조각으로 나눠 이어 그린다(`PencilPainter.Stroke`, 조각 한 묶음에 진하기를 줘서 마커가 이음매에서 진해지지 않음).
- 못 본 것: 조각 이어 그리기의 실제 화면(조각 수가 많아 끊기면 `ChunkPoints`를 키우거나 `MaxPerGroup`을 줄인다).

### 1-3. 다른 시트 (2026-11-16, 사용자: "다른 시트는 밑에 시트 탭으로 화살표가 쓕 간 다음에 돌아오는 이미지가 있으면 더 좋겠다, 간편 설명도")
- 고른 칸이 다른 시트 칸을 쓰거나(쓰는 칸) 다른 시트가 고른 칸을 쓰면(쓰이는 칸), 화면 아래 **시트 탭**을 손으로 빙 두르고 칸에서 탭까지 휘어 내려갔다 돌아오는 화살표 한 쌍을 긋는다. 값이 들어오는 쪽은 돌아오는 화살표가, 나가는 쪽은 내려가는 화살표가 굵다. 탭 위에 손글씨 설명 "매출 시트 G15 에서 가져와요" / "요약 시트 C3 외 1칸 로 보내요". 번호는 가장 먼저(들어옴)와 가장 나중(나감).
- 데이터: 모듈이 `flow.graph`(무거움, 다리 캐시)와 `sheets`(탭 이름 순서)도 구독한다(`role` crossPre, crossDep, tabs). `flow.graph`가 지금 고른 칸의 것일 때만 쓴다. 이 조회는 늦게 도착하므로 **늦게 온 획만 움직이며 덧붙고** 나머지는 그대로 둔다(`SketchStroke.Late`). 스크롤을 따라가는 다시 묻기는 칸 자리(`mark`)만 묻는다.
- **탭 자리는 어림**이다. 엑셀이 시트 탭 줄의 자리를 주지 않아서, 줄은 격자 맨 아래 + 왼쪽 74px(탭 이동 단추 폭), 각 탭 폭은 이름 글자 수(한글 13, 영문 7.5, 여백 26, 최소 48)로 계산한다(`FlowSketch.TabBox`, `ShellController.Marks.BuildCross`). 어긋나면 이 두 곳의 숫자만 고친다. 설명 글이 시트 이름을 말해 주므로 몇 칸 어긋나도 뜻은 통한다.
- 같은 방향 시트는 3개까지, 한 시트의 칸이 여럿이면 "외 N칸".

## 4. 한계 (일부러 안 한 것, 못 본 것)
- 같은 시트의 **보이는 칸만**(조회 `mark`의 한계). 시트를 넘는 흐름은 `hunsu-flowgraph`(목록).
- 활성 칸 하나만 기준(여러 칸을 고른 경우 활성 칸).
- **화면으로 보지 못했다**: 클라우드에는 Windows·엑셀이 없다. 점·시간 계산은 시험으로, 모양은 SVG로 그려 눈으로 확인했지만 WPF 투명 창의 실제 움직임·결 무늬·글꼴 적용은 PC에서 눈으로 확인해야 한다.
- 투명(레이어드) 창은 프레임마다 합성 비용이 든다. 끊기면 `FlowSketch.MaxPerGroup`을 줄이거나 `SetDesiredFrameRate`를 20으로.
