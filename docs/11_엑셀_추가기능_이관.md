# 엑셀 추가기능 → 훈수꾼 이관 (2026-11-16)

원문 지도: `협업/이관지도_칼퇴발_2026-11-16.md`(칼퇴 쪽이 카탈로그 소스를 읽고 만든 분류 A/B/C/D). 이 문서는 훈수꾼 쪽 대조, 사용자 결정, 진행 표다.

## 1. 사용자 결정 (날짜 순)
- 2026-11-16: 추가기능은 더 키우지 않고 새 기능은 훈수꾼에. 칼퇴는 설치·관리 도구. 기존 추가기능은 수리만, 옮길 수 있는 것부터. 카탈로그에서 내리는 시점은 사용자가 정한다(PC에서 눈으로 확인한 뒤).
- 2026-11-16: **쓰기 명령 허용(선택지 가), 단 "실험 기능이며 오류가 날 수 있다"를 먼저 공지하고 사용자가 확인한 뒤에만 쓴다.** docs/01 9장 8번 개정.

## 2. 쓰기 명령 설계 (Claude 추천, 구현 전)
1. **공지**: 쓰기 도구를 처음 켤 때 한 번 "실험 기능입니다. 오류가 날 수 있고 실행 취소(Ctrl+Z)가 안 될 수 있습니다. 먼저 저장하세요."를 보이고 확인해야 켜진다(설정 `writeAck`에 날짜 저장). 판이 바뀌면 다시 묻는다.
2. **실행마다 확인**: "N칸이 바뀝니다"를 매번 묻는다(추가기능과 같음). 한도(칸 수, 보호 시트 거절)는 앱이 한 곳에서.
3. 모듈 선언의 `commands`에 쓰기 명령은 `write.` 접두어로 구분하고 `scope: "write"`가 없으면 막는다.
4. 첫 쓰기 도구 전에 **실행 취소 영향 실측**: 바깥 COM 쓰기가 엑셀 실행 취소 기록에 미치는 영향을 VM(보이지 않는 엑셀, COM만)에서 잰다. 사용자 승인된 VM 시험 범위 안에서, 하기 전에 사용자에게 알린다. 아직 안 했다.
5. 머리(계산)는 C# Core 순수 함수 + 배열 입출력(쪽지 4-2 권장), 칸을 훑는 일(색, 인쇄 설정, 파일)만 다리 VBA. 새 부품(`input`, 확인 창, 공지 창)은 아직 그리는 코드가 없다.

### 2.1 실행 취소 실측 결과 (2026-11-16, VM, Excel 16.0 빌드 20527, 보이지 않는 엑셀, COM만, 빈 임시 파일)
- 외부 COM `Range.Value2`·`Range.Formula` 쓰기 뒤 표준 도구 모음의 실행 취소(Id 128) 컨트롤은 계속 **비활성**: 실행 취소 목록에 오르지 않는 것으로 보인다. `ClearContents` 뒤에만 활성(목록 1개)이 됐고, `Application.Undo`로 되돌려지지는 않았다(해석 미확정).
- `Application.Undo`는 외부 쓰기에 쓸 수 없다(속성 오류). 되돌리기 기능을 앱이 직접 제공하려면 쓰기 전에 값을 앱이 따로 저장해야 한다.
- **못 잰 것**: 사용자가 화면에서 편집한 뒤 외부 COM 쓰기가 끼면 기존 실행 취소 기록이 지워지는지, Ctrl+Z 동작(UI 조작 금지). 알려진 바로는 지워지므로 공지 문구는 "이 작업 뒤 이전 실행 취소가 안 될 수 있습니다"로 쓴다. PC에서 사용자가 눈으로 확인해야 한다.

### 2.2 구현 현황 (판 0.0.041, 다리 0.0.016)
- 앱: `Core/Write/WritePolicy`(순수 규칙, 시험됨), `Shell/ShellController.Write.cs`(공지 → 계획 → 확인 → 실행 → 결과·되돌리기), `Shell/WriteDialog.cs`(작은 모달 창). 공지는 `settings.json`의 `writeAck`가 현재 공지 판(`WritePolicy.NoticeVersion`)과 다르면 처음 쓰기 전에 한 번 보이고, 문구를 바꾸면 판을 올려 다시 보인다. 실행마다 "N건이 바뀝니다" 확인은 늘 뜬다.
- 다리: `CoHunsuDo_Write.bas`. `confirm=1`이 없으면 어떤 경우에도 엑셀을 바꾸지 않는다.
- 첫 단추(각 "보기" 모듈 옆, 이름 끝에 "(실험)"): 숨은 시트 모두 보이기(`hunsu-audit`, 다시 숨기기로 되돌림), 외부 링크 모두 끊기(`hunsu-links`, 되돌리기 없음), 깨진 이름 지우기(`hunsu-names`, 이름 다시 만들기로 되돌림), 마지막 칸 바로잡기(`hunsu-sheetinfo`, 활성 시트만, 되돌리기 없음).
- 아직 없는 것: 값을 입력받는 창(`input`), 새 시트·파일을 만드는 쓰기, 실행 취소 기록이 지워지는지 확인(PC에서 사용자가 눈으로).

## 3. 쪽지와 현재 코드의 차이 (main 00aa688 기준 대조)
- 맞음: 5장 겹침 표, 3-1 숨은 줄 규칙 차이, 4-3 `input`·`toggle`·`tabs` 미렌더(`bar`·`spark`·`progress`는 최근 추가).
- **쪽지에 없던 것**: 앱이 모듈 `params`를 읽는 코드가 없다(`ModuleManifest`가 파싱 안 함). 그래서 추가기능 설정 이어받기(4-4)와 모듈별 색·표시 선택은 앱 작업이 먼저다. 모듈 선언의 `params`는 지금 `[]`, 이관할 때 key 이름은 추가기능 것을 그대로 쓸 것.
- 천 단위 쉼표는 이미 된다(`n` 형식). 글자 크기·시작 때 자동 열기는 모듈 설정이 아니라 앱 설정 몫.
