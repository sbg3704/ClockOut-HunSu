# 코드 규칙과 작업 순서 (초안 v0, 2026-11-11)

칼퇴의 코딩 규칙(칼퇴 저장소 `docs/02_규칙.md` 3장)을 그대로 따르고, 훈수꾼에 필요한 것만 더했다. 이 문서는 "어떻게 쓰고 어떻게 올리는가"를 정한다. 무엇을 만드는지는 `docs/01`, 통신은 `docs/02`, 모습은 `docs/03`, 성능과 안전은 `docs/04`.

## 1. 저장소와 프로젝트
```
ClockOut-HunSu/
  src/
    ClockOut.Hunsu/            실행 파일(WPF). 창, 엑셀 연결, 모듈 찾기
    ClockOut.Hunsu.Ui/         화면 부품(Theme, Controls, Frame)
    ClockOut.Hunsu.Core/       화면과 엑셀 없이 시험되는 계산
    ClockOut.Hunsu.Tests/      Core 시험(xUnit)
  addins/clockout-hunsu/       다리(VBA)
  modules/<모듈id>/            모듈(선언 JSON)
  example/                     예제 모듈
  tools/                       빌드, 패키지, 시험, 측정 스크립트
  vendor/                      받아 둔 공개 라이브러리 원본과 SOURCES.md
  docs/                        규칙 문서
  .github/                     PR 양식
```
- 구조와 규칙 2.1장의 폴더 구조를 이 `src/` 아래로 둔다(칼퇴 저장소와 같은 방식).
- 목표 환경: .NET 8, Windows 10 1607 이상(칼퇴와 같음), `net8.0-windows`, `win-x64`. 칼퇴와 같은 SDK 판을 `global.json`으로 고정한다.
- 공용 코드는 `ClockOut.Core`를 NuGet 패키지로 받아 쓴다. 그 패키지가 나오기 전에는 칼퇴 저장소를 하위 모듈로 연결해 시작한다.

## 2. C# 규칙
- `Nullable` 켬, `ImplicitUsings` 켬, 경고를 오류로(`TreatWarningsAsErrors`). 분석기 경고는 끄지 않고 고친다.
- 파일 하나에 클래스 하나, 한 가지 책임. 권장 300줄, 800줄을 넘기지 않는다. 한 메서드는 한 가지 일(칼퇴 규칙 3장 6, 7번).
- 모든 파일 맨 위에 한국어 주석 세 줄: `기능`, `사용법`, `의존`. 예:
  ```
  // 기능: 엑셀 창 위치를 따라가는 오버레이 창 배치 계산.
  // 사용법: OverlayPlacement.Follow(excelRect, monitorDpi) → 오버레이 사각형.
  // 의존: 없음(순수 계산, 화면과 엑셀을 건드리지 않음).
  ```
- 이름: 클래스와 메서드 `PascalCase`, 지역 변수 `camelCase`, 비공개 필드 `_camelCase`, 상수 `PascalCase`. 약어는 두 글자까지만 대문자.
- **화면 스레드에서 엑셀 호출 금지.** 엑셀에 닿는 코드는 `Excel/` 폴더 안에만 두고 `async`로 감싸 작업 스레드에서 부른다.
- 순수 계산(선언 검증, 자리와 모양 맞추기, 빈도 계산, 메시지 형식)은 `Core`에 두어 화면과 엑셀 없이 `dotnet test`로 시험한다.
- 설정, 저장, 네트워크 접근은 실패해도 앱이 동작하게 항상 실패 처리를 하고 `docs/01` 7.4장의 코드로 기록한다. 빈 `catch`는 실패해도 되는 곳에만, 이유를 주석으로.
- 목록(자리, 모양, 분류, 신호 이름, 조회 이름)을 코드에 박지 않고 선언과 규격 파일에서 읽는다.
- XAML 파일에는 배치와 연결만 두고 계산을 넣지 않는다. 색, 크기, 시간은 `Theme`에서만 가져온다(`docs/03` 11장).

## 3. VBA 규칙
`docs/02` 9장을 따른다. 요약: CP949+CRLF, `Declare`는 `PtrSafe` 두 갈래, 예약어와 겹치는 변수 이름 금지, 범용 함수는 `clockout-lib`에, 파일 300줄 안팎, 조회 하나에 파일 하나, 모든 공개 프로시저에 `On Error`. 컴파일은 PC에서 보이지 않는 엑셀로 확인한다.

## 4. 이름과 번호
- 모듈 id `hunsu-<이름>`(영문 소문자, 숫자, 하이픈), 다리 id `clockout-hunsu`, 틀 실행 파일 `ClockOut.Hunsu.exe`.
- 판 번호 `vX.Y.Z`, 무게 +1, +10, +100은 칼퇴 규칙과 같다. 번호는 판을 낼 때 한 번만 매기고 작업 중에는 무게만 보고한다. Release 태그: 틀 `hunsu-vX.Y.Z`, 다리 `clockout-hunsu-X.Y.Z`, 모듈 `<모듈id>-X.Y.Z`.
- 일 번호는 `일#12`, PR 번호는 `PR#3`으로 구분한다. GitHub에 올라가는 글에는 `일#12`로 쓴다.

## 5. 브랜치, 커밋, PR (인수인계를 위해)
계정을 기능으로 나누지 않는다. 누가 이어받아도 되도록 **기록으로 잇는다.**
- 브랜치: `claude/h-<세부>-<일번호>-<슬러그>`. 세부는 `shell`, `ui`, `bridge`, `mod`, `docs`, `tools`. 시작은 최신 `main` 위에서 한다. 합쳐진 브랜치는 새 일에 다시 쓰지 않는다.
- 커밋: 제목은 무엇을 했는지(한 줄), 본문은 **왜 그렇게 했는지와 버린 대안**. 한 커밋은 한 가지 일.
- PR 본문은 `.github/pull_request_template.md`의 여섯 항목을 모두 채운다: ① 무엇을 왜 ② 끝난 것 ③ 남은 일과 다음 할 일 ④ 확인한 범위와 못 한 것 ⑤ 관련 결정(문서 장 번호) ⑥ 먼저 읽을 파일.
- 작업이 끝나거나 멈출 때 `HANDOFF.md`의 "지금 상태, 다음 할 일, 막힌 것"을 갱신한다.
- 사용자가 정한 것은 대화나 메모리에만 두지 말고 `docs/`에 날짜와 함께 적는다. 새 규칙은 이 폴더 문서에 적는다.
- 바이너리(`.xlam`, 실행 파일, zip)는 커밋하지 않고 Release로 올린다.

## 6. 시험과 확인
- `dotnet test`는 `Core`와 `Ui`의 순수 부분을 시험한다. 새 계산에는 시험을 함께 쓴다.
- 다리는 `tools/test_bridge.ps1`로 보이지 않는 엑셀에서 COM으로 호출해 JSON을 검증한다(`docs/02` 9장).
- 성능은 `tools/bench`로 재고 결과를 PR에 붙인다(`docs/04` 5장).
- **사용자 PC에서 키보드, 마우스, 화면 조작으로 시험하지 않는다.** 엑셀은 보이지 않는 인스턴스(`Visible=False`)와 COM으로만 다룬다.
- 화면은 틀이 스스로 그려 저장한 그림(스크린샷 도구)으로 확인한다.
- 클라우드에는 엑셀과 Windows 그래픽이 없어 컴파일, 화면, 성능을 확인할 수 없다. PR에 "클라우드에서 확인한 것 / PC에서 확인해야 할 것"을 나눠 적는다.

## 7. 오픈소스 받는 절차
1. 먼저 모 라이브러리(`clockout-lib`, `ClockOut.Core`, `Ui`)와 이미 받아 둔 것에 있는지 찾는다.
2. 후보를 고른다: 허용형 라이선스(MIT, ISC, BSD, Apache-2.0), 관리가 이어지는 것, 최신 판(특별한 이슈가 없으면 최신으로 시작한다).
3. NuGet은 정확한 판으로 고정하고, 그림과 글꼴은 `vendor/<이름>/`에 원본 그대로 둔다.
4. `vendor/SOURCES.md` 표에 한 줄을 더한다: 이름, 출처 주소, 판 또는 커밋, 받은 날짜, 라이선스, 작성자, 수정 여부, 쓰는 곳.
5. 배포물 `licenses/` 폴더에 라이선스 전문을 넣는다.
6. 모듈과 다른 코드가 직접 부르지 않게 `Ui` 또는 `Core`가 한 번 감싸서 내준다.

## 8. 단계별 일 목록과 끝 기준
단계는 `docs/01` 11장과 같다. 각 단계는 PR 하나 이상이고, 끝났다고 하기 전에 `docs/04` 9장 점검표를 지난다.

**0단계: 연결 시험 (가장 먼저, 확인할 것이 많아서)**
- [ ] 솔루션 뼈대(`src/`), `global.json`, 빌드 스크립트, 빈 시험 프로젝트.
- [ ] 오버레이 창 한 개: 투명, 클릭 통과 구역, 엑셀 창 이동·크기·최소화 따라가기(`SetWinEventHook`).
- [ ] 다리 최소판: `Hello`, `selection.summary`, `sel` 신호.
- [ ] 신호 방식 확인: 창 메시지 + 공유 메모리 우체통이 VBA에서 안전한지(안 되면 대안으로 전환).
- [ ] 호출 거절(셀 편집 중) 코드와 재시도 효과, 엑셀 두 개와 재시작에서 끊김 없음.
- [ ] `tools/bench`로 성능 예산 4개(선택→화면, 패널 열기, 다리 시간, 창 이동 어긋남) 측정.
- 끝 기준: 측정 결과가 `docs/04` 1장 목표 안이거나, 못 지킨 항목과 원인, 대안이 문서에 적혀 있다.

**1단계: 틀의 뼈대** 패널 틀(제목줄, 핀, 접기, 투명도), 가장자리 도크와 핀 창, 이동과 저장, 예제 모듈 "선택 요약".
**2단계: 자리 채우기** 상시 띠, 셀 위 표시층, 호출층, 배치 편집, 예제 모듈이 모든 자리에 놓임.
**3단계: 모듈 늘리기** 오류 셀, 시트 이동, 수식 순서도.
**4단계: 규격 공개** 카탈로그 `apps` 구역, 칼퇴 레일 연동(칼퇴 저장소 일), 보조 모니터 자리, 추가기능의 조회 등록.

## 9. 문서를 고치는 법
- 규칙이 바뀌면 코드를 고치기 전에 해당 문서를 먼저 고치고 PR에 장 번호를 적는다.
- 문서 번호는 `docs/NN_이름.md`. 초안이 확정되면 파일 이름에서 "초안"을 뺀다.
- 문서와 코드가 다르면 코드가 맞다고 보고 문서를 고친다.
