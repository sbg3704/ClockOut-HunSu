# 훈수꾼 구조와 규칙 (초안 v0, 2026-11-11)

훈수꾼은 엑셀 창 위에 정보를 겹쳐 보여 주는 칼퇴의 하위 프로그램이다. 이 문서는 구현을 시작하기 전에 정해 둘 구조와 규칙을 모은 초안이다. 기존 칼퇴 규칙(`docs/02_규칙.md`, `docs/03`, `docs/06_commands_규격.md`)을 그대로 따르고, 설계로(Web_PMIS_GIS)에서 이미 검증된 방식(`docs/02` 모듈 규약, `docs/08` 모·자 라이브러리와 공개 라이브러리, `docs/11` 표준, `docs/25` 공통 부품)을 가져왔으며, 훈수꾼에만 필요한 것을 더했다. 확정되면 파일 이름에서 "초안"을 뺀다.

맨 아래 12장에 결정 목록이 있다. 2026-11-11 사용자가 7개를 모두 정했다. 화면 기술은 "가장 예쁘고 화려하되 반응성이 가장 중요, 메모리는 200~300MB 늘어도 괜찮다"는 기준으로 WPF 네이티브(GPU 그리기) + 선언형 모듈로 확정했다(3.7장). 웹 화면(WebView2)은 나중에 선택형으로 열어 둔다.

## 1. 부르는 이름

| 대상 | 보이는 이름 | 코드 이름 | 설명 |
|---|---|---|---|
| 전체 | 훈수꾼 | `hunsu` | 칼퇴의 하위 프로그램 |
| 틀 | 훈수꾼 | `ClockOut.Hunsu` | 자리, 패널 틀, 엑셀 연결을 맡는 실행 파일 |
| 다리 | 훈수꾼 다리 | `clockout-hunsu` | 엑셀 안에서 신호를 보내고 조회에 답하는 VBA 추가기능 |
| 모듈 | (이름) 모듈 | `hunsu-<이름>` | 틀에 꽂아 내용을 채우는 단위. 예: 오류 셀 모듈 `hunsu-errors` |
| 자리 | 자리 | `place` | 모듈이 놓이는 곳 여섯 종류 |
| 모양 | 모양 | `shape` | 모듈이 자리에 맞춰 그리는 형태 다섯 종류 |

## 2. 저장소와 파일 구조

**확정(2026-11-11 사용자 결정): 훈수꾼 전용 저장소를 새로 만든다.** 틀, 다리, 모듈 소스, 공개 라이브러리 원본, 규칙 문서를 모두 그 저장소에 둔다. 칼퇴(`ClockOut`)와는 코드를 직접 섞지 않고 아래 두 곳으로만 만난다.

- **공용 코드**: 설정, 동기화, 선언 공통 필드 읽기, 판 비교는 `ClockOut.Core`를 NuGet 패키지로 받아 쓴다. 그러려면 칼퇴가 `ClockOut.Core`를 패키지로 내보내야 한다(칼퇴 쪽 작업, 3.4장 6·7번 규칙 때문에 필요). 패키지로 내보내기 전에는 칼퇴 저장소를 하위 모듈로 연결해 시작한다.
- **배포**: 훈수꾼 판은 칼퇴가 읽는 카탈로그 목록(`catalog.json`의 새 구역 `apps`)에 등록하고 Release로 올린다. 칼퇴 좌측 레일이 이 목록을 읽어 아이콘으로 보여 주고, 사용자가 고르면 받아서 설치한다(2.4장).
- 저장소 이름과 공개 여부는 사용자가 정한다(12장). 공개 저장소가 아니면 칼퇴가 받을 수 없으므로, 실행 파일과 모듈 zip은 기존처럼 공개 `ClockOut-Catalog`의 Release로 올리는 길을 권한다.

아래 2.1~2.3장의 폴더 구조는 전용 저장소의 루트를 기준으로 읽는다(`hunsu/`를 빼고 읽으면 된다).

### 2.1 훈수꾼 저장소 (틀)

```
hunsu/
  ClockOut.Hunsu/              실행 파일. 창과 연결만 맡는다
    Program.cs
    Shell/                     자리 여섯 종류, 패널 틀, 배치 편집, 호출 단축키
    Excel/                     엑셀 창 따라가기, 다리 호출, 신호 받기
    Bus/                       데이터 통로(구독, 캐시, 빈도 제한)
    Modules/                   모듈 찾기, 선언 읽기, 화면 선언을 부품으로 바꾸기
    Overlay/                   오버레이 창(투명, 클릭 통과 구역), 엑셀 창 따라가기
  ClockOut.Hunsu.Core/         화면과 엑셀 없이 시험되는 계산
    Manifest/                  모듈 선언 읽기와 검증
    Layout/                    자리와 모양 맞추기, 배치 계산, 자석 붙기
    Protocol/                  신호, 조회, 명령의 메시지 형식
    Throttle/                  갱신 빈도 계산
  ClockOut.Hunsu.Tests/        Core 시험
  ClockOut.Hunsu.Ui/           화면 부품 모음(WPF 라이브러리). 모듈이 선언으로 부르는 모든 부품
    Theme/                     색, 글꼴, 간격, 그림자, 효과, 애니메이션 한 벌(디자인 값은 여기만)
    Controls/                  목록, 배지, 단추, 큰 숫자, 막대, 입력, 순서도 같은 부품
    Frame/                     패널 틀(제목줄, 핀, 접기, 투명도)
  vendor/                      받아 둔 공개 라이브러리(판 고정, SOURCES.md)
  example/                     새 모듈의 시작점이 되는 예제 모듈
docs/01_구조와_규칙.md          이 문서
```

- 프로젝트는 기존 `app/ClockOut.sln`에 추가한다. `ClockOut.Hunsu.Core`는 `ClockOut.Core`를 참조하고(설정, 동기화, 판 비교), 반대 방향 참조는 없다.
- 매니저(`ClockOut.App`)는 훈수꾼 코드를 참조하지 않는다. 실행 파일을 켜고 끄고, 모듈을 설치하고, 설정 화면을 보여 줄 뿐이다.

### 2.2 다리와 모듈 (훈수꾼 저장소 안, 배포는 카탈로그 Release)

```
addins/clockout-hunsu/                 다리. 기존 라이브러리와 같은 방식
  clockout-hunsu.clockout.json         type "library", category "라이브러리"
  CoHunsuApi.cls                       밖에서 부르는 진입점
  CoHunsuEntry.bas                     시작과 끝, 틀 찾기
  CoHunsuSignal.bas                    변화 감지와 신호 보내기
  CoHunsuEvents.cls                    Application 이벤트
  CoHunsuQ_<조회>.bas                  조회 하나에 파일 하나
  CoHunsuDo.bas                        명령 실행
hunsu/<모듈id>/                         모듈
  <모듈id>.hunsu.json                   선언
  README.md
  view.json                            화면 선언(모양별로 어떤 부품을 쓰는지, 4.1장). 코드 파일은 없다
tools/build_hunsu.ps1                  모듈 폴더를 검사하고 zip 만들기
tools/publish_hunsu.ps1                Release와 catalog.json 등록
catalog.json                           모듈은 최상위 키 "modules"(항목마다 app: "hunsu"), 틀은 "apps"(2.4장)
```

- 조회 함수는 모두 다리 안에 둔다. 모듈이 새 데이터가 필요하면 다리에 `CoHunsuQ_<조회>.bas`를 더하고 다리 판을 올린다. 모듈은 선언에 필요한 다리 최소 판을 적는다.
- 다리는 공용 라이브러리(`clockout-lib`)에 의존할 수 있고, 기능 추가기능에는 의존하지 않는다(기존 라이브러리 원칙).
- 나중 확장: 기능 추가기능이 자기 조회를 다리에 등록하는 길은 규격 공개 단계에서 연다. 그 전에는 닫아 둔다.

### 2.4 칼퇴 좌측 레일과 하위 프로그램 (칼퇴 쪽 작업)

사용자 결정(2026-11-11): 칼퇴 창 왼쪽에 **레일**을 둔다. 레일은 칼퇴가 관리하는 하위 프로그램(지금은 훈수꾼, 앞으로 CAD 리습, PPT 등)을 아이콘으로 보여 주는 세로 띠다.

- 레일 맨 위는 지금 화면(추가기능 관리)이고, 그 아래에 하위 프로그램 아이콘이 놓인다.
- 아이콘 상태 세 가지: **받을 수 있음**(카탈로그에는 있고 PC에는 없음, 흐리게 + 받기 점), **설치됨**(실행 중 표시 포함), **업데이트 있음**(배지). 새로 올라온 하위 프로그램은 레일에 알림 점으로 알려 준다.
- 아이콘을 누르면 그 프로그램의 소개, 받기·업데이트·실행·끄기·제거가 한 화면에 나온다. 설치와 업데이트는 추가기능과 같은 안전 규칙(SHA-256 확인, 원자적 교체, 되돌리기, 작업 기록)을 쓴다.
- 목록은 코드에 박지 않고 `catalog.json`의 `apps` 구역(`id`, `name`, `version`, `icon`, `description`, `url`, `sha256`, `size`, `host`)에서 읽는다. 아이콘 그림도 카탈로그에서 받는다(작은 PNG 또는 SVG).
- 하위 프로그램 실행은 칼퇴가 맡는다(Windows 시작 때 같이 켜기, 설정 화면에서 켜고 끄기). 하위 프로그램이 죽어도 칼퇴는 영향이 없다.
- 이 작업은 칼퇴 저장소의 일이다. 훈수꾼 0단계와 병행해 칼퇴 새 판에서 만들고, 레일 화면 시안은 별도로 그려서 확인받는다.

### 2.3 사용자 PC

```
<칼퇴 데이터 폴더>/hunsu/
  modules/<모듈id>/         설치된 모듈(선언과 화면)
  layout.json               배치(어느 모듈이 어느 자리에, 크기, 투명도)
  state.json                마지막 상태(접힘, 핀). 동기화하지 않음
```

- 모듈별 설정은 기존 추가기능 설정과 같은 곳에 같은 방식으로 저장한다.
- 동기화: `layout.json` 내용은 설계로 동기화 데이터의 `settings` 아래에 넣는다(최상위 키는 늘리지 않는다, 256KB 제한). 화면 크기가 다른 PC를 위해 위치는 픽셀이 아니라 "어느 가장자리, 몇 번째"로 저장한다.

## 3. 코드 구조

### 3.1 층과 방향

```
모듈 화면 선언  →  틀 Ui(부품)  →  틀 Bus  →  틀 Excel  →  다리 (VBA)  →  Excel
                                 ↑
                              Hunsu.Core (계산, 시험 대상)
```

- 화살표 방향으로만 부른다. 모듈은 선언만 하고, 선언을 부품으로 바꾸고 그리는 일은 틀이 한다.
- 모듈끼리는 서로 부르지 않는다. 같은 데이터가 필요하면 각자 같은 주제를 구독한다.
- 엑셀에 닿는 코드는 틀의 `Excel/` 폴더와 다리뿐이다.

### 3.2 언어별 역할

| 층 | 언어 | 이름 규칙 |
|---|---|---|
| 다리 | VBA | 모듈 이름 `CoHunsu*`, 공개 함수 `CoHunsu_*`. 지역 변수에 예약어와 겹치는 이름 금지 |
| 틀 | C# (.NET 10 LTS) | 네임스페이스 `ClockOut.Hunsu.*`, 기존 앱과 같은 규칙 |
| 화면 | C# + XAML (WPF, .NET 10) | 틀 안의 부품에만 쓴다. 모듈은 화면 코드를 갖지 않고 JSON 선언만 쓴다(3.7장) |
| 무거운 분석 | C# 우선 | 재 보고 느릴 때만 다른 언어 검토 |

### 3.3 세 가지 통로

| 통로 | 방향 | 방식 | 형식 |
|---|---|---|---|
| 신호 | 다리 → 틀 | 창 메시지 | `신호이름|책|시트` 한 줄. 내용은 싣지 않는다 |
| 조회 | 틀 → 다리 | 다리 함수 호출 | `CoHunsu_Query(이름, 인자JSON)` → JSON 글자열 |
| 명령 | 틀 → 다리 | 다리 함수 호출 | `CoHunsu_Do(이름, 인자JSON)` → JSON 글자열 |

응답은 설계로 서버 API(`docs/11` 5장)와 같은 틀을 쓴다: `{"ok": true, "proto": 0, "data": ...}` 또는 `{"ok": false, "proto": 0, "error": "사람이 읽는 한국어", "code": "고정 코드"}`. 화면과 작업 기록은 `code`로 판단하고 `error`는 그대로 보여 준다.

**식별자**(2026-11-12 추가): 틀은 대상을 네 가지 번호로 구분한다. 엑셀 인스턴스(프로세스 번호), 엑셀 창(창 핸들), 책 세션 번호(다리가 책이 열릴 때 매기는 실행 중 번호, 이름이나 경로로 책을 구분하지 않는다. 같은 이름, 저장 전 책이 있기 때문), 시트(책 세션 번호 + 시트 `CodeName`). 조회는 `Application.Run`이 끝날 때 답이 오는 동기 호출이라 요청 번호는 틀 안의 큐에서만 쓴다.

모듈은 위 통로를 직접 만지지 않는다. 선언에 "어떤 데이터(주제)를 받아 어떤 부품으로 보여 주고, 눌렀을 때 어떤 명령을 보낼지"만 적으면(4.1장) 틀이 구독, 조회, 그리기, 명령 보내기를 맡는다. 신호는 선택 주소처럼 짧은 값은 함께 실어 보낼 수 있다(화면이 조회를 기다리지 않고 먼저 반응하기 위해서).

### 3.7 화면 기술과 반응성 (확정)

사용자 기준(2026-11-11): 가장 예쁘고 화려한 방향, 메모리 200~300MB 증가는 괜찮다, **반응성이 가장 중요하다.** 그래서 브라우저를 거치지 않고 WPF로 GPU에서 직접 그린다.

**왜 WPF 네이티브인가**: 같은 프로세스에서 그려 입력과 그리기 사이에 프로세스 간 통신이 없고, 추가 런타임 설치가 없으며(.NET 8 포함, 칼퇴와 같은 조건), 벡터와 애니메이션, 효과(그림자, 흐림, 셰이더)를 GPU로 낼 수 있다. 화려함은 `Theme`와 부품에 한 번 공들이면 모든 모듈이 함께 얻는다.

**반응성 규칙**
1. **화면은 엑셀을 기다리지 않는다.** 엑셀 호출은 엑셀 인스턴스마다 하나씩 둔 **전용 STA 스레드**(메시지 펌프와 `IMessageFilter`를 갖춤)에서만 하고, 결과는 큐로 화면 스레드에 넘긴다. `Task.Run`이나 스레드 풀에서 엑셀 객체를 만지지 않는다. 응답이 오래 없으면 연결을 끊고 다시 찾으며, 엑셀이 끝나면 COM 참조를 정리한다. 화면 스레드에서 엑셀 호출 금지.
2. **신호가 오면 먼저 반응하고 내용은 나중에 채운다.** 선택 주소 같은 짧은 값은 신호에 실어 즉시 보여 주고, 요약과 목록은 조회가 끝나는 대로 부드럽게 바꾼다.
3. **오버레이 창은 엑셀 창당 하나.** 투명한 한 장의 창에 모든 자리를 그리고, 패널이 없는 곳은 클릭이 아래 엑셀로 통과하게 한다(구역별 hit test). 창이 여러 개일 때 생기는 위치 어긋남과 깜빡임을 없앤다.
4. **투명은 하드웨어 방식으로.** WPF의 `AllowsTransparency`(소프트웨어 그리기)를 쓰지 않고, DWM 합성(투명 HwndSource + `DwmExtendFrameIntoClientArea`)으로 GPU 가속을 유지한다. 흐림 배경은 Windows 11의 공식 배경 효과를 쓰고, 지원하지 않는 PC는 반투명 색으로 대체한다.
5. **엑셀 창 따라가기는 이벤트로.** 엑셀 창 이동, 크기, 최소화는 `SetWinEventHook`으로 받아 즉시 따라간다(반복 확인 금지).
6. **애니메이션은 GPU가 하는 것만.** 투명도, 이동, 크기 변환만 움직이고 배치를 다시 계산하는 속성은 움직이지 않는다. 긴 목록은 보이는 줄만 그린다(가상화).
7. **무거운 계산은 화면 밖에서.** 순서도 배치, 정렬, 검색은 별도 스레드에서 하고 결과를 캐시한다. 화면은 마지막 결과를 먼저 보여 준다.
8. **미리 떠 있는다.** 훈수꾼은 칼퇴와 함께 시작해 숨은 상태로 준비하고(ReadyToRun), 엑셀이 앞에 오면 즉시 나타난다. 처음 켜질 때 로딩을 보지 않게 한다.

**반응성 목표**(0단계에서 재고, 못 지키면 설계를 고친다): 선택을 바꾼 뒤 화면에 반영되기까지 50ms 이내(짧은 값 기준), 패널 열기 100ms 이내, 애니메이션 60fps, 다리가 엑셀에서 쓰는 시간 5ms 이내, 엑셀 창을 끌 때 오버레이가 한 프레임 이상 어긋나지 않음. 측정은 사용자 PC에서 키보드나 마우스를 쓰지 않고 COM으로 선택을 옮겨 가며 한다.

**메모리**: 상시 300MB 이내를 목표로 하되 반응성과 화려함이 먼저다. 숨김 상태에서는 그림 캐시를 줄인다.

### 3.4 공용 코드 (같은 코드를 두 번 짜지 않는다)

설계로의 모·자 라이브러리 방식(`docs/08`, `docs/25`)을 세 언어에 똑같이 적용한다.

| 언어 | 모 라이브러리(모두가 씀) | 자 라이브러리(한 곳만 씀) | 받아 온 공개 라이브러리 |
|---|---|---|---|
| C# | `ClockOut.Core`(설정, 동기화, 선언 공통 필드, 판 비교, 안전 검사), `adapters/excel` | `ClockOut.Hunsu.Core` | NuGet 패키지(판 고정) |
| VBA | `clockout-lib`(Co* 모듈) | 다리 안의 `CoHunsu*` | `clockout-vendor-*`(JSON은 `clockout-vendor-data`) |
| 화면 | `ClockOut.Hunsu.Ui`(Theme, Controls, Frame) | 모듈 선언(코드 없음) | NuGet 패키지(판 고정), `vendor/`(그림, 글꼴) |

지킬 규칙:

1. **만들기 전에 먼저 찾는다.** 새 기능을 짜기 전에 모 라이브러리와 받아 둔 공개 라이브러리에 이미 있는지 본다. 각 모 라이브러리의 README에 함수 목록을 두고 고칠 때 함께 갱신한다.
2. **없으면 공용에 먼저 더하고, 그다음 가져다 쓴다.** 모듈이나 화면 파일 안에 범용 함수를 짜 넣지 않는다.
3. **둘이 쓰면 올릴 후보, 셋이 쓰면 올린다.** 두 모듈이 같은 화면 요소를 선언으로 흉내 내면 `Controls`로 올릴 후보로 적어 두고, 셋째가 생기면 부품으로 만든다.
4. **라이브러리는 값만 돌려준다.** 창을 띄우거나 엑셀을 건드리지 않는다. 화면 부품은 자기 모양만 그리고 데이터 조회나 엑셀 호출을 하지 않는다.
5. **공개한 이름과 뜻은 바꾸지 않는다.** 바꿔야 하면 새 이름으로 더한다. 예전 모듈이 깨지지 않게 하기 위해서다.
6. **선언 읽기는 한 곳에서.** `clockout.json`과 `hunsu.json`의 공통 필드(`id`, `version`, `dependencies`, `params` 등)는 `ClockOut.Core/Manifest`가 읽고, 훈수꾼은 덧붙은 필드만 읽는다. 매니저와 훈수꾼이 선언 파서를 따로 갖지 않는다.
7. **엑셀 연결은 한 곳에서.** 실행 중인 엑셀 찾기와 호출 재시도는 `adapters/excel`에 더해 매니저와 훈수꾼이 같이 쓴다.
8. **다리에 범용 함수를 두지 않는다.** 범위 훑기, 오류 판별, 글자 처리처럼 다른 추가기능도 쓸 만한 것은 `clockout-lib`에 더하고(라이브러리 담당에게 요청) 다리는 불러 쓴다. JSON 만들기는 `clockout-vendor-data`를 쓴다.
9. **디자인 값은 한 벌.** 색, 글꼴, 간격, 그림자, 효과, 애니메이션 시간은 `Ui/Theme` 한 곳에만 둔다. 모듈 선언은 값을 직접 쓰지 않고 이름(예: `tone: warn`)으로만 쓴다.
10. **새 모듈은 예제에서 시작한다.** `example/`을 복사해 내용만 바꾼다. 예제는 부품의 권장 사용법을 늘 최신으로 보여 준다.

### 3.5 오픈소스 활용 (다 짜지 않고 받아 쓴다)

방침은 설계로(`docs/08` 공개 라이브러리, `docs/25` 4장)와 칼퇴 카탈로그(`vendor/vba/SOURCES.md`)를 그대로 따른다.

- 직접 짜기 전에 공개 라이브러리를 먼저 찾아본다. 틀이 꼭 스스로 해야 하는 것(자리, 패널 틀, 다리 규격)만 직접 짠다.
- 고르는 기준: 무료이고 허용형 라이선스(MIT, ISC, BSD, Apache-2.0). GPL 계열과 상용 겸용은 쓰지 않는다. 관리가 이어지고 있는 것.
- 받는 법: **정확한 판을 고정**해 저장소에 둔다. C#과 화면용은 NuGet 판 고정(패키지 복원 목록을 저장소에 둔다), 그림과 글꼴은 `vendor/<이름>/`, VBA용은 기존 `vendor/vba/`. 출처, 판, 라이선스, 받은 날짜, 쓰는 곳을 `SOURCES.md`에 적고 원본은 고치지 않는다. 배포물에는 라이선스 전문을 함께 넣는다.
- 받아 온 것은 `Ui`가 한 번 감싸서 내준다. 모듈과 다른 코드가 공개 라이브러리를 직접 부르지 않게 해야 나중에 다른 것으로 바꿀 수 있다.
- 12장 7번 결정(처음에 넓게 받아 둔다)에 따라, 아래 후보 중 화면 기술에 맞는 것을 0~1단계에서 한꺼번에 받아 판을 고정하고 `SOURCES.md`에 적는다.

쓸 자리와 후보(도입할 때 판과 라이선스를 다시 확인한다):

### 3.6 기존 코딩 규칙에서 그대로 가져오는 것

- 파일 하나는 한 가지 책임. 권장 300줄, 800줄을 넘기지 않는다. 조회 하나에 파일 하나.
- 모든 소스 맨 위에 한국어 주석으로 기능, 사용법, 의존하는 것.
- 순수 계산은 `Hunsu.Core`로 빼서 엑셀 없이 시험한다.
- 목록(자리, 모양, 분류, 신호 이름)을 코드에 박지 않고 선언과 규격에서 읽는다.
- 실패해도 엑셀과 칼퇴는 멀쩡해야 한다. 다리가 없거나 판이 낮으면 훈수꾼은 조용히 쉬고 이유를 작업 기록에 남긴다.

## 4. 선언 방식

모듈은 `<모듈id>.hunsu.json` 하나로 자기를 소개한다. 추가기능 선언(`clockout.json`)과 공통 필드, `dependencies`, `params` 형식을 똑같이 쓴다. 매니저의 설정 화면과 의존성 안내를 그대로 재사용하기 위해서다.

```json
{
  "spec": 0,
  "id": "hunsu-errors",
  "name": "오류 셀",
  "version": "0.1.000",
  "host": "excel",
  "category": "점검",
  "author": "ClockOut",
  "description": "현재 시트의 오류 셀을 모아 보여 주고, 어디서 시작됐는지 알려 줍니다.",
  "dependencies": [
    {"id": "clockout-hunsu", "min_version": "0.1.000", "reason": "오류 셀 조회에 훈수꾼 다리를 씁니다"}
  ],
  "shapes": ["mark", "chip", "tab", "panel", "window"],
  "place": "edge-right",
  "order": 200,
  "data": [
    {"topic": "errors", "on": ["change", "sheet"], "weight": "normal"}
  ],
  "commands": ["goto"],
  "params": [
    {"key": "showRoot", "label": "시작점 표시", "type": "bool", "default": true}
  ]
}
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `spec`, `id`, `name`, `version`, `host`, `category`, `author`, `description` | 예 | 추가기능 선언과 같다 |
| `dependencies` | 예 | 다리와 그 밖의 의존성. 형식은 기존과 같다 |
| `shapes` | 예 | 그릴 수 있는 모양. 하나 이상 |
| `place` | 예 | 처음 놓일 자리. `shapes`로 놓을 수 있는 자리여야 한다 |
| `order` | 아니오 | 같은 자리 안에서의 기본 순서. 없으면 500 |
| `data` | 아니오 | 구독할 주제, 다시 받을 신호, 무게 |
| `commands` | 아니오 | 쓸 명령 이름. 적지 않은 명령은 틀이 막는다 |
| `scope` | 아니오 | 읽을 수 있는 범위(권한). `selection` < `sheet`(기본) < `book` < `books`(열린 다른 책까지). 틀은 조회 인자가 이 범위를 넘으면 막고, 설치 화면에 범위를 보여 준다 |
| `params` | 아니오 | 사용자 설정. 형식은 기존과 같다 |

검증은 기존 방식대로 한다. 필수 필드가 없거나 형식이 틀리면 그 모듈만 건너뛰고 이유를 작업 기록에 남긴다. `spec`이 틀보다 높으면 "훈수꾼을 업데이트하세요"로 안내한다.

### 4.1 화면 선언 (`view.json`)

모듈은 화면 코드를 쓰지 않고, 모양별로 어떤 부품에 어떤 데이터를 연결할지만 적는다. 틀이 부품으로 바꿔 그린다. 아래는 오류 셀 모듈의 예(초안)다.

```json
{
  "chip":  { "text": "오류 {errors.count}", "tone": "warn", "hideWhen": "errors.count == 0" },
  "tab":   { "title": "오류", "badge": "{errors.count}", "tone": "warn" },
  "panel": [
    { "type": "stat", "value": "{errors.count}", "label": "오류 셀", "tone": "warn" },
    { "type": "list", "items": "errors.items",
      "row": { "title": "{addr}", "sub": "{reason}", "badge": "{kind}", "tone": "{tone}",
               "onClick": { "do": "goto", "addr": "{addr}" } } }
  ],
  "mark":  { "cells": "errors.items", "addr": "{addr}", "tag": "{note}", "tone": "warn" }
}
```

- 부품 초기 목록: `stat`(큰 숫자), `list`(행 목록), `text`, `badge`, `button`, `toggle`, `input`(검색), `bar`(막대·진행), `spark`(작은 추세 그림), `flow`(순서도), `tabs`, `divider`. 새 부품은 `Ui/Controls`에 더하고 목록과 예제를 함께 갱신한다.
- `tone`은 `info`, `good`, `warn`, `bad`, `muted` 다섯 가지로 고정하고 실제 색은 `Theme`가 정한다(밝은 화면, 어두운 화면 모두).
- 값이 바뀔 때의 움직임(숫자 굴러가기, 새 줄 미끄러져 들어오기, 오류가 생길 때의 부드러운 강조)은 부품이 기본으로 갖는다. 모듈이 움직임을 따로 적지 않는다.
- 선언에 쓸 수 있는 표현은 데이터 연결(`{...}`)과 조건 한 줄뿐이다. 계산과 분기가 필요하면 다리의 조회나 틀의 부품으로 올린다. 그래서 모듈은 코드를 실행하지 않고, 공개 카탈로그의 모듈도 PC에서 코드를 돌리지 못한다.
- 나중에 정말 자유로운 화면이 필요한 모듈이 생기면, 그때 "웹 화면 모듈"(WebView2)을 선택형으로 더한다. 규격에 `viewType` 자리를 비워 두고 지금은 `declarative`만 쓴다.

## 5. 자리와 모양

| 자리 코드 | 이름 | 쓰는 모양 | 클릭 |
|---|---|---|---|
| `mark` | 셀 위 표시층 | mark | 통과 |
| `strip` | 상시 띠 | chip | 통과(조각을 누르면 그 모듈의 패널이 열림) |
| `edge-left`, `edge-right` | 가장자리 도크 | tab(접힘), panel(펼침) | 받음 |
| `summon` | 호출층 | window | 받음 |
| `pin` | 핀 창 | window | 기본 통과, 호출 중에만 받음 |
| `second` | 보조 모니터 | window | 받음 |

- 셀 위 표시(`mark`)는 자리이면서 다른 자리와 함께 켜진다. 오류 셀 모듈이 도크에 있어도 셀 테두리는 그려진다. 표시만 따로 끌 수 있다.
- 모양별 크기 약속: chip은 한 줄 24자 이내, tab은 이름과 배지 하나, panel은 너비 220~320 고정에 세로로 흐름, window는 최소 320×200에 크기 조절 가능.
- 모든 모듈은 호출층에 나올 수 있어야 한다. `window`가 없으면 틀이 `panel`을 창 안에 넣어 보여 준다. 그래서 `panel`과 `window` 중 하나는 반드시 있어야 한다.

## 6. 우선순위 규칙

### 6.1 누구 말이 먼저인가
사용자가 정한 것 > 모듈 선언 > 틀 기본값. 사용자가 옮긴 자리, 순서, 켜고 끈 것은 모듈을 업데이트해도 유지한다.

### 6.2 자리 안 순서 (`order`)
100 단위로 띄워 쓴다. 숫자가 작을수록 앞(위, 왼쪽)이다.

| 범위 | 쓰는 곳 |
|---|---|
| 100~199 | 늘 봐야 하는 상태(선택 요약, 계산 모드 경고) |
| 200~299 | 점검(오류 셀, 깨진 링크) |
| 300~399 | 이동(시트, 이름 범위) |
| 400~499 | 수식(순서도, 참조) |
| 500~899 | 그 밖(기본값 500) |
| 900~999 | 참고와 메모 |

### 6.3 갱신 무게 (`weight`)
엑셀을 느리게 하지 않는 것이 먼저다. 틀이 무게에 따라 조회를 늦추거나 건너뛴다.

| 무게 | 뜻 | 틀의 처리 |
|---|---|---|
| `light` | 선택 영역만 보는 조회 | 신호 뒤 0.1초 기다렸다 조회 |
| `normal` | 시트 하나를 훑는 조회 | 입력이 0.5초 멈추면 조회. 보이는 모듈만 |
| `heavy` | 책 전체나 참조 관계를 따라가는 조회 | 사용자가 열었을 때와 새로 고침을 눌렀을 때만 |

- 화면에 보이지 않는 모듈(접힘, 숨김)은 `tab`과 `chip`에 필요한 숫자만 받는다.
- 엑셀이 바쁘거나 셀 편집 중이면 조회를 미루고 마지막 내용을 흐리게 유지한다. 세 번 미뤄지면 다음 신호까지 쉰다.

### 6.4 공간이 모자랄 때
가장자리 도크가 넘치면 `order`가 큰 것부터 손잡이로 접는다. 띠가 넘치면 `order`가 큰 조각부터 "더 보기"로 넣는다.

### 6.5 알림 등급
`info`(띠 조각의 숫자만 바뀜), `notice`(잠깐 뜨는 알림), `alert`(사용자가 닫을 때까지 남음). 모듈은 등급만 정하고 표시 방식은 틀이 맡는다. `alert`는 틀이 승인한 모듈만 쓴다.

## 7. 번호 규칙

### 7.1 판 번호
기존 `vX.Y.Z` 규칙과 무게(+1, +10, +100)를 그대로 쓴다. 틀, 다리, 모듈이 각자 판을 가진다.

| 대상 | Release 태그 | 예 |
|---|---|---|
| 틀 | `hunsu-vX.Y.Z` | `hunsu-v0.1.000` |
| 다리 | `clockout-hunsu-X.Y.Z` | 기존 추가기능 태그 방식 |
| 모듈 | `<모듈id>-X.Y.Z` | `hunsu-errors-0.1.000` |

### 7.2 규격 번호
정수 두 개를 따로 센다. 형식이 깨지게 바뀔 때만 올린다.

- `spec`: 모듈 선언 형식. 0부터.
- `proto`: 신호, 조회, 명령의 통신 형식. 0부터. 모든 응답에 실린다.

틀은 자기보다 높은 `spec`이나 `proto`를 만나면 그 모듈이나 다리를 쓰지 않고 업데이트를 안내한다. 낮은 번호는 한 단계 아래까지 받아 준다.

### 7.3 이름 규칙 (신호, 조회, 명령)
영문 소문자, 낱말은 점으로 잇는다. 한번 공개한 이름은 뜻을 바꾸지 않고, 바꿔야 하면 새 이름을 만든다.

| 종류 | 초기 목록 |
|---|---|
| 신호 | `sel`(선택 바뀜), `change`(값 바뀜), `sheet`(시트 전환), `book`(책 열림·닫힘·전환), `calc`(계산 끝), `mode`(편집 시작·끝) |
| 조회 | `selection.summary`, `sheets`, `errors`, `precedents`, `book.info` |
| 명령 | `goto`, `sheet.activate` |

### 7.4 오류 코드
설계로처럼 뜻이 고정된 영문 코드를 쓴다(번호가 아니라 이름). 사람에게 보이는 문장은 `error`에 한국어로 따로 싣는다. 한번 정한 코드는 뜻을 바꾸지 않는다.

| code | 뜻 | 훈수꾼의 처리 |
|---|---|---|
| `excel_missing` | 엑셀이 실행 중이 아님 | 숨고 기다림 |
| `excel_busy` | 편집 중이거나 대화상자가 떠 있음 | 마지막 내용을 흐리게 유지하고 나중에 다시 |
| `bridge_missing` | 다리가 설치되지 않았거나 꺼져 있음 | 칼퇴에서 켜도록 안내 |
| `bridge_old` | 다리 판이 모듈이 요구하는 것보다 낮음 | 업데이트 안내 |
| `query_unknown` | 다리에 없는 조회 이름 | 그 모듈만 쉼, 작업 기록 |
| `query_failed` | 조회 중 오류 | 그 모듈에 "불러오지 못함" 표시 |
| `manifest_bad` | 모듈 선언이 틀림 | 그 모듈만 건너뜀 |
| `spec_newer` | 선언이나 통신 규격이 틀보다 새것 | 훈수꾼 업데이트 안내 |
| `view_failed` | 모듈 화면을 불러오지 못함 | 그 패널에 다시 시도 단추 |
| `store_failed` | 배치나 설정 저장 실패 | 메모리에만 두고 다음에 다시 저장 |

### 7.5 일 번호와 브랜치
기존 규칙 그대로. 범위 코드에 `h`(훈수꾼)를 더한다. 세부는 `shell`, `web`, `bridge`, `mod`. 예: `claude/h-shell-41-edge-dock`.

## 8. 분류 규칙

- 다리는 기존대로 `라이브러리`. 목록에서 늘 맨 위에 온다.
- 모듈 분류는 하는 일이 아니라 "사용자가 무엇을 얻는가"로 나눈다. 분류는 코드에 박지 않고 선언에서 읽으며, 아래는 권장 목록이다.

| 분류 | 넣는 것 | 기본 `order` 범위 |
|---|---|---|
| 요약 | 선택 요약, 책 정보, 계산 모드 | 100번대 |
| 점검 | 오류 셀, 깨진 링크, 숨은 시트 | 200번대 |
| 이동 | 시트 이동, 이름 범위, 최근 위치 | 300번대 |
| 수식 | 순서도, 참조 보기 | 400번대 |
| 참고 | 메모, 단축키 표 | 900번대 |

- 새 분류는 모듈이 세 개 이상 모일 때만 만든다. 그 전에는 가장 가까운 분류에 넣는다.
- 매니저의 [찾기]와 [추가기능] 탭에는 "훈수꾼" 구역을 따로 두고, 그 안에서 분류로 묶는다.

## 9. 형태 원칙 (확정된 방향)

1. 평소에는 셀을 가리지 않는다.
2. 키 입력을 뺏지 않는다. 훈수꾼을 눌러도 타이핑은 엑셀로 간다.
3. 정보만 있는 것은 클릭이 통과한다.
4. 단축키 하나로 전부 부르고, 하나로 전부 숨긴다.
5. 엑셀이 앞에 있을 때만 보인다. 창을 옮기면 따라가고, 대화상자나 편집 중에는 흐려진다.
6. 모든 패널은 같은 틀을 쓴다.
7. 위치는 배치 편집 상태에서만 바꾼다.
8. 다리는 읽기와 이동만 한다. 셀 값을 바꾸지 않는다(실행 취소 기록 보호).

## 10. 시험과 완료 기준

- `Hunsu.Core`는 `dotnet test`로 시험한다. 선언 검증, 자리와 모양 맞추기, 빈도 제한, 메시지 형식이 대상이다.
- 다리는 기존 추가기능처럼 보이지 않는 엑셀에서 컴파일을 확인한다.
- 사용자 PC에서 키보드 입력과 화면 조작으로 시험하지 않는다. 화면은 틀이 스스로 찍은 그림으로 확인한다.
- 단계마다 "엑셀이 느려지지 않았는가"를 잰다. 기준: 선택을 바꿀 때 다리가 쓰는 시간 5ms 이내, `normal` 조회 한 번 100ms 이내(1만 셀 시트).

### 12-0. 외부 검토 의견 반영 (2026-11-12)
사용자가 받아 온 타당성 검토(GPT)를 대조해 다음을 반영했다. 받은 것: .NET 10, 전용 STA 스레드(3.7장), 식별자(3.3장), 단축키 등록 방식(12-1), 카탈로그 구역 이름(`apps` 하위 프로그램, `modules` 훈수꾼 모듈, `addins` 추가기능), 모듈 권한 `scope`(4장), 공유 메모리는 실측으로 필요할 때만(다리 규격 4장), 성능을 구간별·P95로 재기(성능과 안전 1장), 종속 셀 조회 `dependents`, 클릭 통과를 먼저 하고 키보드 포커스는 뒤 단계, 칼퇴 없이도 단독 실행·시험(코드 규칙 1장).
받지 않은 것(모듈이 10개쯤 될 때 다시 본다): 데이터 중개자·자원 관리자·진단 관리자·의존성 해석기·확장 등록소 같은 중앙 관리 층, 유료 모델과 시장 조사, 서명된 카탈로그(서명 없이 배포하기로 한 결정 유지), 사용자 파일럿. 같은 조회를 여러 모듈이 구독하면 한 번만 부르는 일은 이미 버스의 주제 구독이 맡는다.

### 12-1. 호출 단축키 판단 (사용자 요청: 실수로 누르기 어렵고 H로 기억하기 쉬움)

| 동작 | 키 | 이유 |
|---|---|---|
| 훈수꾼 부르기·닫기 | **Ctrl+Alt+H** | 세 키를 동시에 눌러야 해서 실수가 거의 없고, H는 훈수 머리글자다. 엑셀 기본 키에 없다(Ctrl+H는 바꾸기, Alt+H는 홈 탭이라 둘 다 피함) |
| 전부 숨기기·쉬게 하기 | **Ctrl+Alt+Shift+H** | 같은 키에 Shift를 더한 것으로 기억하기 쉽다. 발표나 화면 공유 때 바로 끄는 용도 |

- `RegisterHotKey`는 등록해 둔 동안 그 키를 다른 프로그램에서 빼앗는다. 그래서 **엑셀(또는 훈수꾼 창)이 앞에 올 때 등록하고, 다른 프로그램이 앞에 오면 해제한다**(앞 창 변화는 이미 쓰는 `SetWinEventHook`으로 안다). 이렇게 해야 다른 프로그램에서는 그 키가 그대로 그 프로그램에 간다(2026-11-12 고침. 앞 문장은 등록만으로 된다고 잘못 적었었다).
- 등록에 실패하면(다른 프로그램이 이미 쓰는 키) 알림으로 알리고 설정에서 다른 키를 고르게 한다. 기본값은 사용자가 바꿀 수 있고, 같은 키를 쓰는 칼퇴 추가기능 명령과 겹치면 기존 단축키 표의 충돌 검사를 같이 쓴다.
- 칼퇴 `commands` 규격 문서의 예시 키 `^+H`(Ctrl+Shift+H)는 예시일 뿐이므로 훈수꾼 키와 헷갈리지 않게 추가기능 쪽 예시를 다른 키로 바꾸는 것을 권한다.
- Windows 11의 Win+H(받아쓰기), 한글 입력기의 한/영·한자 키와는 겹치지 않는다.

## 13. 인수인계 규칙 (확정: 계정을 나누지 않고 기록으로 잇는다)

사용자 결정(2026-11-11): 계정 1·2를 기능으로 나누는 방식은 사용량만 쓰고 실속이 적다. 일은 사용자가 필요와 사용량에 따라 나누고, 누가 이어받아도 되도록 **커밋과 PR에 경과를 적는다.**

- **PR 본문 필수 항목**: ① 무엇을 왜 했는지 한두 문장 ② 끝난 것 ③ 아직 안 한 것과 다음에 할 일 ④ 확인한 범위(컴파일, 시험, 엑셀에서 확인 여부와 못 한 것) ⑤ 정해진 것과 사용자 결정 링크(문서 장 번호) ⑥ 이어받는 사람이 먼저 읽을 파일 3개 이내.
- **커밋 메시지**: 제목은 무엇을 했는지, 본문은 왜 그렇게 했는지와 버린 대안을 적는다. 한 커밋은 한 가지 일만 한다.
- **작업이 끝나거나 멈출 때**: 저장소 맨 위 `HANDOFF.md`의 "지금 상태, 다음 할 일, 막힌 것"을 갱신한다.
- **결정은 문서에 적는다**: 사용자가 정한 것은 대화나 메모리에만 두지 않고 이 문서(확정되면 저장소 `docs/`)에 장 번호와 날짜로 남긴다.
- 계정 소유 표나 대기·요청 절차는 만들지 않는다.
