# 알려진 문제와 고칠 방향: 범위 선택 때 떨림과 엑셀 버벅임 (2026-11-12)

상태: 배포 판이 아닌 시험 단계(0.0.001). 이 문서는 **버그와 방향만** 적는다. 코드는 아직 고치지 않았다.

## 증상 (사용자 보고, 2026-11-12)
칼퇴 레일로 설치·켜기까지는 잘 되고 훈수꾼도 작동한다. 그런데 엑셀에서 **범위를 선택(끌기)하면 훈수꾼 패널이 계속 떨리고, 엑셀도 버벅인다.**

## 원인 (코드를 읽고 추정. PC에서 측정해 확인하지는 않았다)
1. **엑셀 조회가 쉬지 않고 이어진다.** `Excel/InstanceRegistry.cs`의 `OnSignal`은 조회가 끝나면 그동안 쌓인 마지막 신호로 곧바로 다음 조회를 한다(`next = inst.Pending`). 범위를 끌면 `SheetSelectionChange`(다리 `CoHunsuEvents.cls`)가 셀이 바뀔 때마다 신호를 보내므로, 끄는 내내 엑셀 화면 스레드가 `Application.Run`을 처리하느라 바쁘다. 대기 시간이 없고 마우스 버튼 상태도 보지 않는다.
2. **조회 한 번이 무겁다.** `CoHunsuQ_SelectionSummary.bas`는 선택 영역과 사용 범위가 겹치는 곳을 `Value2` 배열로 읽은 뒤 VBA `For Each`로 칸마다 센다(최대 100만 칸, VBA 루프). 영역마다 `SpecialCells(xlCellTypeFormulas)`도 부른다. 선택이 클수록 한 번에 수백 ms에서 수 초가 걸릴 수 있다. (docs/04 1장의 "다리 시간 5ms" 목표는 신호 보내기만이고, 조회는 별개다.)
3. **바쁨 표시가 깜빡임으로 보인다.** 조회가 250ms(`SlowCallMs`)를 넘으면 `Slow` 이벤트가 패널을 반투명(`SetStale(true)`, `ModuleView.cs`, `ShellController.cs:46`)으로 만들고, 결과가 오면 다시 불투명으로 돌아온다. 끄는 동안 이 두 상태가 계속 반복된다.

## 고칠 방향 (제안, 사용자 확인 전)
- **신호 묶기(디바운스)**: 마지막 신호 뒤 약 120ms 조용할 때만 조회한다. 조회 사이에 최소 간격(예: 지난 조회 시간의 몇 배)을 둔다.
- **끄는 동안 미루기**: 마우스 왼쪽 버튼이 눌려 있으면 조회를 미룬다(`GetAsyncKeyState`). 키보드로 영역을 넓힐 때(Shift+방향키 길게 누름)는 위의 최소 간격으로 막는다.
- **바쁨 표시 완화**: 이미 이전 값이 보이면 반투명으로 바꾸지 않는다. 600ms 이상 걸릴 때만 표시하고, 표시와 해제 사이에 최소 유지 시간을 둔다.
- **VBA 조회를 싸게**: 선택이 약 1만 칸을 넘으면 워크시트 함수(`Count`, `CountA`, `Sum`, `Min`, `Max`)로 세고, 오류 수는 `SpecialCells(xlCellTypeFormulas/Constants, xlErrors)`로, 수식 수 세기는 큰 선택에서는 생략하거나 근사로 둔다. 시간 상한을 넘기면 `truncated:true`로 끝낸다. VBA 소스는 CP949 + CRLF를 지킨다(`tools/vba_to_cp949.ps1`).
- **측정 기준 추가**: 큰 범위(예: 10만 칸 이상)를 끌 때 엑셀 입력 지연과 훈수꾼 조회 횟수를 `tools/bench`에 넣어, 고친 뒤 PC에서 재어 확인한다(docs/04 측정 규칙).

## 확인이 필요한 것
- 위 원인 1~3 중 어느 것이 가장 큰지는 PC 측정(`ClockOut.Hunsu.Bench`의 조회 시간, 신호 횟수)으로 가려야 한다. 코드 추정만으로는 순서를 못 정한다.
- 훈수꾼을 끄면(레일 [끄기]) 버벅임이 사라지는지 먼저 확인하면 원인이 훈수꾼 쪽이라는 것이 굳어진다.

## 관련
- 같은 날 발견된 별개 문제: `tools/pack_app.ps1`을 Windows PowerShell 5.1로 돌리면 zip 항목 이름이 역슬래시로 들어가 칼퇴가 "안전하지 않은 경로"로 거부한다. `pwsh`(PowerShell 7)로 돌리면 정상. 고칠 방향: 어떤 PowerShell에서도 항목 이름을 `/`로 쓰게 한다(`ZipArchive.CreateEntry`로 직접 쓰기), 시작할 때 `pwsh` 여부를 점검한다.
