# 함수도우미 「한 수」 설계 (2026-11-20, 1단계 구현 2026-11-21 판 0.0.225)

수식을 **만드는 데** 돕는 모듈. 풀이(읽기)는 이미 수식 흐름·색연필 흐름이 하므로 여기서는 하지 않는다.

## 0. 결정 기록
- 2026-11-18 사용자: "수식풀이는 이미 있다. 내가 생각하는 도우미는 만드는 데 도움 주는 도우미."
- 2026-11-20 사용자 선택(카드): **찾기 + 짜 주기 한 흐름**. 하고 싶은 일로 함수를 찾고, 범위를 끌어 빈칸을 채우면 수식을 완성해 칸에 넣는다.
- 보류: 수식을 치는 동안 옆에 뜨는 힌트(아래 6장). 엑셀 편집 중 COM 거절 때문에 따로 시험이 필요하다.
- 2026-11-20 사용자 선택(카드): 모듈 이름 **한 수**(`hunsu-hansu`). 훈수꾼이 수식 한 수를 둬 준다는 뜻.

## 1. 쓰는 흐름
1. **넣을 칸 잡기**: 모듈을 열 때 고른 칸을 "넣을 칸"으로 기억한다(`Sheet1!D5`). 빈칸을 채우느라 선택이 움직여도 넣을 칸은 그대로다. [이 칸으로] 단추로 바꾼다.
2. **찾기**: 글 상자에 하고 싶은 일을 친다. "조건 합", "ㅈㄱㅎ"(초성), "vlookup", "찾아서 가져오기" 모두 된다. 후보 5개가 뜻 한 줄, 예시 한 줄과 함께 뜬다. 글 상자가 비면 "자주 쓰는 함수"와 "최근 쓴 함수"를 보여 준다.
3. **빈칸 채우기**: 함수를 고르면 빈칸 줄이 나온다(SUMIFS면 "더할 범위", "조건 범위 1", "조건 1", [＋ 조건 더하기]). 빈칸을 누르면 그 칸이 "듣는 중"이 되고, 엑셀에서 범위를 끌면 주소가 들어간다(다른 시트면 `'시트'!A1:A9`). 조건·글자 칸은 직접 친다. 빈칸마다 $ 고정 단추(F4처럼 4단 돌기).
4. **미리 보기**: 아래에 완성 수식과 지금 계산 값이 뜬다. 빠진 빈칸은 흐리게, 틀린 것(범위 크기가 다름 등)은 이유 한 줄.
5. **넣기**: [넣기]를 누르면 넣을 칸에 쓴다. 칸이 비어 있지 않으면 쓰기 명령의 계획 단계로 "덮어씁니다" 확인을 거친다. [되돌리기]는 기존 값 되돌리기 저장을 같이 쓴다.

"조용한 훈수"(docs/09)에 맞게, 이 모듈은 사용자가 열었을 때만 움직이고 저절로 뜨지 않는다.

## 2. 함수 사전 (파일로 둔다)
`modules/hunsu-hansu/functions.ko.json` 하나. 함수를 더하려면 코드가 아니라 이 파일에 한 덩어리를 더한다.

```json
{
  "name": "SUMIFS",
  "group": "더하기·세기",
  "say": "조건에 맞는 칸만 더합니다",
  "words": ["조건 합", "조건부 합계", "골라서 더하기", "sumif"],
  "args": [
    { "key": "sum",  "label": "더할 범위",   "kind": "range" },
    { "key": "crit_range", "label": "조건 범위", "kind": "range", "repeat": "crit" },
    { "key": "crit", "label": "조건",        "kind": "criteria", "repeat": "crit" }
  ],
  "example": "=SUMIFS(D:D, B:B, \"서울\")",
  "needs": "2007"
}
```
- `kind`: `range`(끌어서), `value`(숫자·칸), `text`(따옴표 자동), `criteria`(">=10", "서울", 칸 주소를 알아서 감쌈), `bool`(참/거짓 고르기), `func`(다른 함수를 안에 넣기, 2단계).
- `repeat`: 같은 이름끼리 묶어 [＋ 더하기]로 늘린다(SUMIFS 조건 쌍, IFS 조건·값 쌍).
- `needs`: 쓸 수 있는 엑셀 판. `365`(XLOOKUP, FILTER, UNIQUE, LET 등)는 사용자 엑셀이 못 쓰면 후보 끝으로 내리고 표시한다.
- 처음 넣을 함수(약 40개): 더하기·세기(SUM, SUMIFS, COUNT, COUNTA, COUNTIFS, AVERAGEIFS, MAXIFS, MINIFS, SUMPRODUCT, SUBTOTAL), 조건(IF, IFS, IFERROR, AND, OR, SWITCH), 찾기(VLOOKUP, XLOOKUP, INDEX, MATCH, XMATCH), 숫자(ROUND, ROUNDUP, ROUNDDOWN, ABS, MOD), 날짜(DATE, TODAY, EDATE, EOMONTH, DATEDIF, NETWORKDAYS, WEEKDAY), 글자(LEFT, MID, RIGHT, LEN, TEXT, TEXTJOIN, SUBSTITUTE, TRIM), 배열(UNIQUE, FILTER, SORT). 뜻·낱말은 쓰면서 늘린다.

## 3. 나누기 (순수 계산은 Core, 시험 가능)
| 곳 | 하는 일 |
|---|---|
| Core `Formula/FunctionCatalog` | 사전 파일 읽기와 검사(빠진 칸, 같은 이름) |
| Core `Formula/FunctionSearch` | 찾기: 낱말 맞춤, 초성 맞춤(ㅈㄱㅎ), 영어 이름 앞부분, 최근·자주 가중치. 오픈소스 없이 작은 코드로 충분(초성은 유니코드 계산) |
| Core `Formula/FormulaBuilder` | 빈칸 값 → 수식 글자. 글자 따옴표·이스케이프, 시트 이름 따옴표, `$` 돌기, 반복 묶음, 빈 선택 인자 생략 |
| Core `Formula/FormulaCheck` | 미리 보기 전 검사: 빠진 필수 칸, SUMIFS 범위 크기 다름, 괄호 |
| Ui 새 부품 | `input`(글 상자, 아직 없음 docs/11 4-3), `slot`(누르면 선택을 듣는 빈칸), 함수 후보 `list`의 누르기 |
| 셸 | 듣는 빈칸이 있으면 기존 선택 신호(`selection.summary`의 `addr`·`sheet`)를 그 빈칸에 넣는다. 새 조회 없음 |
| 다리(VBA) | 조회 `formula.preview {formula, at}`: `Evaluate`로 값만 돌려줌(쓰지 않음, 무게 normal). 명령 `write.formula.set {at, formula, confirm}`: 쓰기 규칙(계획→실행) 그대로, 365 수식은 `Formula2`, 아니면 `Formula`. 바뀐 칸은 기존 되돌리기 저장 |

- 수식 글자는 영어 함수 이름 + 쉼표(`Range.Formula`)로 만든다. 사용자의 엑셀이 한국어여도 엑셀이 알아서 바꿔 보여 준다.
- 엑셀이 편집 중(입력 모드)이면 넣기·미리 보기가 거절된다. 그때는 "엑셀에서 Esc로 입력을 끝내 주세요" 한 줄만 보이고, 넣기 단추는 엑셀이 풀릴 때까지 다시 시도한다.

## 4. 단계
1. **0.0.x +10**: Core 4개 + 시험, 사전 파일(40개), Ui `input`·`slot`, 다리 `formula.preview`·`write.formula.set`, 시나리오 시트("함수도우미": 품목·지역·금액 가짜 표, SUMIFS로 서울 합 넣기). 
2. 함수 안에 함수(`func` 빈칸: IFERROR 안에 VLOOKUP), 최근 쓴 함수 기억(설정 저장).
3. 지금 칸 수식 불러와 고치기(이미 있는 수식을 빈칸으로 다시 펼치기, 수식 파서 필요: 오픈소스 후보 XLParser(MPL-2.0이라 허용형인지 확인 필요) 또는 작은 자체 토큰 나누기).

## 5. 확인할 것 (PC)
- 빈칸이 듣는 중일 때 범위 끌기 → 주소가 바로 들어오는지(선택 신호 지연).
- 다른 시트 범위를 고른 뒤 넣을 칸 시트로 돌아오지 않아도 넣기가 되는지.
- 한국어 엑셀에서 넣은 수식이 한국어 함수 이름으로 보이는지(지금 엑셀은 함수 이름을 번역하지 않는다, 쉼표만 지역 설정).

## 6. 보류: 치는 중 힌트
수식을 치는 동안에는 COM이 거절되므로 엑셀에서 수식 글자를 못 읽는다. 길은 UI Automation으로 수식줄 글자를 읽는 것뿐이고, 엑셀 판마다 다르고 한글 입력기와 부딪힐 수 있다. 1단계가 끝난 뒤 PC에서 작은 시험(수식줄 글자 읽기만)을 해 보고 정한다. docs/20 1번(참조 팝업)과 같은 제약이다.

## 7. 1단계 구현에서 정한 것 (2026-11-21, 판 0.0.225, 다리 0.0.021)
- **따로 뜨는 창**: 독·사이드바 패널은 키보드를 받지 않는 창(WS_EX_NOACTIVATE)이라 글 상자를 둘 수 없다. 그래서 패널은 선언만(넣을 칸 안내 + [한 수 두기], 앱 명령 `app.hansu.open`)이고, 찾기·빈칸은 맨 위에 뜨는 작은 창 `Shell/HansuWindow.cs`(+ `.Slots.cs`)에 둔다. view.json 부품(`input`)을 새로 만들지 않았다.
- **듣는 빈칸**: 빈칸 글 상자를 누른 뒤 바뀐 선택만 받는다. 범위 빈칸은 통째로 바꾸고, 글이 있는 식 빈칸은 커서 자리에 끼워 넣으며, 선택이 또 바뀌면 방금 넣은 자리만 바꾼다(엑셀 수식 입력과 같게).
- **값 미리 보기는 넣기 확인 창에서**: 계획 단계에서 다리가 `Worksheet.Evaluate`로 계산해 보여 준다. 창 안 실시간 값은 다리 호출이 잦아져 미뤘다(2단계 후보).
- **최근 쓴 함수**는 앱을 켜 둔 동안만 기억한다(설정 저장은 2단계).
- 코드: Core `Formula/`(FunctionCatalog, FunctionSearch, Hangul, FormulaDraft, FormulaRef), 시험 `FormulaTests`, 셸 `ShellController.Hansu.cs`, 다리 `CoHunsuDo_WriteFormula.bas`, 시나리오 시트 「한수」.
