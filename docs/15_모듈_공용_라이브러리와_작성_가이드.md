# 모듈 공용 라이브러리와 작성 가이드 (2026-11-17, 판 0.0.097)

사용자 말씀(2026-11-17): "라이브러리화는 더 확장해야 해. 차후 기능들도 생각해서, 혼자 쓰는 기능은 모듈이 구현할 부분만이고 나머지는 라이브러리에서 받아오는 게 좋겠다." 그리고 "독이 왼쪽, 패널들이 오른쪽."

## 1. 원칙
모듈은 코드가 없고 **선언 두 파일**(`<id>.hunsu.json`, `view.json`)만 갖는다. 모듈이 적는 것은 "무엇을 보일지(주제·글·조건)"와 "어디에·어떤 모양으로"뿐이고, 창을 만들고 따라다니고 숨기고 저장하는 일은 전부 셸과 공용 부품이 한다. 새 기능을 위해 셸을 고쳐야 한다면 그것이 빠진 공용 부품이다 → 선언 한 칸을 공용에 더한다.

## 2. 독 배치 (2026-11-17 사용자 결정)
- 독(훈 원·아이콘)은 **왼쪽 하나**, 열린 패널은 그 **오른쪽**에 붙는다. 모듈 선언의 기본 `place`는 모두 `edge-left`(실제 선언 27개 전부, 시험 `RealModules_AllPlacedLeftByDefault_...`가 지킨다). 오른쪽 독은 사용자가 모듈 관리자에서 [오른]으로 옮겼을 때만 나타나고, 모듈이 없는 독은 창째 숨는다(`UpdateDockVisibility`). 핀을 풀면 선언 자리가 도크가 아닐 때도 왼쪽으로 돌아간다.
- 이전엔 `hunsu-pencilflow`만 `edge-right`였고 빈 오른쪽 독도 훈 원을 그려 "독이 오른쪽에도 있다"로 보였다. 둘 다 고쳤다.

## 3. 모듈이 쓸 수 있는 선언 (한눈에)
| 하고 싶은 것 | 어디에 | 셸 코드 |
|---|---|---|
| 엑셀 값을 받아 패널에 보이기 | manifest `data`(주제·신호·무게) + view.json `panel` | 없음 |
| 모양: 패널 / 떼어 낸 반투명 창 / 줄여서 시작 | manifest `form`(`panel`·`hud`·`mini`) | 없음 |
| 떼어 낸 창의 처음 크기 | manifest `size {"width","height"}`(없으면 테마 `Hunsu.HudWidth/Height`) | 없음 |
| **커서 옆·고른 칸 옆을 따라다니는 글** | manifest `hud`(HudSpec.cs 머리말) | 없음 |
| 우클릭 빠른 설정·설정 창 [옵션] | manifest `quick`(toggle·choice·menu, order, group) | 없음 |
| **전역 단축키로 켜고 끄기** | quick toggle의 `hotkey`("Ctrl+Alt+D", 엑셀이 앞일 때만 등록, 허브 우클릭 메뉴에도 자동) | 없음 |
| 설정이 바뀐 뒤 다시 그리기/다시 묻기 | quick 항목의 `apply`(`redraw`·`refresh`) | 없음 |
| 셀 위 그림(상자·밑줄·색연필) | view.json `marks[]`(`style`, `items`, `tone`, 켜고 끄는 설정 `enabledKey`) | 새 style이면 `IMarkStyle` 하나 |
| 단추·목록 줄이 보내는 명령 | manifest `commands`(허용 목록), view.json의 부품 | 없음 |

### hud 예 (`hunsu-selection`)
```json
"form": "hud", "size": {"width": 250, "height": 170},
"hud": {"anchor": "cursor", "enabledKey": "cursorHud", "anchorKey": "hudAnchor",
        "when": "selection.summary.count > 0",
        "parts": [ {"text": "합계 {selection.summary.sum:n} · {selection.summary.nonEmpty:n0}개", "when": "selection.summary.sum != null"},
                   {"text": "{selection.summary.count:n0}칸", "when": "selection.summary.sum == null"},
                   {"text": "오류 {selection.summary.errors:n0}", "when": "selection.summary.errors > 0"} ]}
```
`anchor`는 `cursor`(범위를 끄는 동안) 또는 `cell`(고른 칸 옆 계속). `anchorKey`가 가리키는 설정이 있으면 그 값이 우선이라 사용자가 바꿀 수 있다. 고른 칸 옆을 쓰는 HUD가 하나라도 켜져 있으면 셸이 `mark` 조회를 자동으로 더 받는다. 글·조건 문법은 `Template`·`Condition`(코드 실행 없음).

## 4. 이번에 셸에서 걷어 낸 모듈 전용 코드
| 전에 | 지금 |
|---|---|
| `CursorHud`가 셸에 박혀 `selection.summary`를 직접 읽고 "합계 …" 글을 만듦(`Quick.cs`) | manifest `hud` 선언. 셸은 `ShellController.Hud.cs`가 선언을 읽어 모듈마다 창 하나를 운영 |
| 떼어 낸 창 기본 크기 250×170, 자리 24/200이 숫자로 박힘 | 테마 토큰 `Hunsu.HudWidth/Height/RightGap/Top` + 모듈 `size` |
| `Marks.cs`의 `"pencil"` 분기와 `BuildCross` 등 색연필 전용 코드 | `MarkStyles`(등록처) + `PencilMarkStyle`. 새 그리기 방식은 `IMarkStyle`만 더하면 됨 |
| 켜고 끄기를 `style != "pencil"`과 `_settings.PencilDraw`로 판단 | marks 선언의 `enabledKey` |
| `QuickMenu.cs`의 `pencilDraw`·`pencilLook`, `ApplySetting`의 `hudAnchor` 분기 | quick의 `apply` 선언(`OnQuickApply`) + hud 설정 키는 선언에서 읽음(`OnHudSettingChanged`) |
| `selection.summary` 글자가 `InstanceRegistry`·`Modules.cs`에 흩어짐 | `TopicRouting.SelectionSummary` 한 곳(앱이 직접 쓰는 유일한 주제: 지연 측정과 최근 이동 기록) |

변한 동작 하나: 커서 HUD는 이제 `count > 0`이면 보인다(전에는 합계가 없으면 "N칸"). 고른 칸 옆 모드는 전에 `count > 1`일 때만 보였는데 선언 `when` 하나로 합쳤으니 한 칸일 때도 "1칸"이 뜬다. 거슬리면 `when`을 `> 1`로 고치면 된다(코드 수정 없음).

## 5. 27개 모듈 전수 점검 (남은 모듈 전용 코드)
- 선언만으로 일하는 것: 26개(패널·단추·목록·차트·표시층·빠른 설정 전부 공용). 셸에 모듈 이름이 박힌 곳은 위 표를 고친 뒤 **없다**(`grep hunsu-`로 `HunsuSettings.EnabledByDefault`의 기본 켜짐 목록과 `Profiles`의 작업 묶음만 남음: 둘 다 데이터 목록이다).
- 앱 안에 남은 모듈 전용 코드: **없음**(0.0.097에서 마저 옮김).
  1. 단축키: Ctrl+Alt+D가 `HotkeyPolicy`에서 빠지고 pencilflow 선언의 `hotkey`가 됐다. `HotkeyChord`(순수 읽기, 시험됨, 훈수꾼 자체 키·수식키 없는 글자 키·F13 이상은 거절) → `HotkeyService.SetModuleChords`(번호 100부터) → `ShellController.Hotkeys.cs`. 같은 키를 두 모듈이 선언하면 앞선 모듈 것만 쓴다.
  2. 설정 창 [일반]에서 모듈 전용 줄(색연필 모양, 커서 HUD 스위치, 합계 HUD 붙는 곳)을 뺐다. 같은 값은 [옵션] 쪽과 아이콘 우클릭에 모듈 선언대로 나온다.
  3. 앱 서비스(`app.history`)는 앱의 일이라 그대로. 모듈 설정을 설정 파일에서 모듈별로 모으는 일(`HunsuSettings`의 `PencilLook`·`CursorHud` 속성)은 설정 파일 호환 때문에 일부러 안 했다: 값 읽기·쓰기는 이미 키 글자로 일반화돼 있어 새 모듈은 속성이 필요 없다.
  4. 부채 런처: 잠들 때 훈 원 속으로 완전히 접히고 깨어날 때 한 칸씩 차례로 펼친다(전에는 반만 움직여 펼쳐지는 느낌이 약했음).

## 6. 새 모듈을 쓸 때 순서
1. `modules/hunsu-<이름>/`에 선언 두 파일. 본뜰 만한 모듈: 상태 `hunsu-selection`, 목록 `hunsu-errors`, 그림 `hunsu-marks`.
2. 코드를 쓰고 싶어지면 멈추고 위 표에서 맞는 선언 칸이 있는지 본다. 없으면 공용에 칸을 더한다(순수 계산은 `Core`, 시험 포함).
3. `tools/make_scenarios.py`에 시나리오 한 줄, 판 번호 올리기, `HANDOFF.md` 갱신.

- 공개 저장소이므로 비공개 정보(회사 자료, 내부 경로, 비밀값)는 넣지 않는다.
