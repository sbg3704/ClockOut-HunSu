# 다리 규격 (초안 v0, 2026-11-11)

다리는 엑셀 안에서 도는 VBA 추가기능 `clockout-hunsu`다. 틀(훈수꾼 프로그램)과 엑셀 사이의 모든 통신이 여기를 지난다. 이 문서의 이름, 형식, 한도는 한번 공개하면 뜻을 바꾸지 않는다(구조와 규칙 3.4장 5번). 아래에서 **[0단계 확인]** 표시는 실제 엑셀에서 재 보고 확정할 것이다.

## 1. 다리가 하는 일과 하지 않는 일
- 한다: 엑셀의 변화를 알리고(신호), 물어보면 모아서 답하고(조회), 이동 명령을 실행한다(명령).
- 하지 않는다: 화면 그리기, 셀 값이나 서식 바꾸기, 파일 저장, 엑셀 설정(`ScreenUpdating`, `Calculation`, `EnableEvents` 등) 바꾸기, 대화상자(`MsgBox`) 띄우기. 이동 명령 외에는 선택 영역과 활성 시트도 바꾸지 않는다.
- 어떤 상황에서도 엑셀 사용자에게 오류 창이 뜨면 안 된다. 다리의 모든 공개 프로시저는 `On Error`로 감싸 JSON 오류를 돌려준다.

## 2. 파일 구성 (`addins/clockout-hunsu/`)
| 파일 | 맡는 일 | 규칙 |
|---|---|---|
| `CoHunsuApi.bas` | 밖에서 부르는 진입점(`Hello`, `Query`, `Do`) | 얇게. 이름으로 조회·명령 파일에 나눠 줄 뿐. **표준 모듈이어야 한다**(`Application.Run`은 클래스 메서드를 부르지 못함, 0단계 확인 2026-11-12) |
| `CoHunsuEntry.bas` | 시작과 끝, 이벤트 연결 켜기·끄기 | 시작 시 틀 창을 찾지 못해도 정상 동작 |
| `CoHunsuEvents.cls` | `Application` 이벤트(`WithEvents`) | 처리 시간 5ms 이내, 셀 읽기 금지 |
| `CoHunsuMail.bas` | 신호 보내기(창 메시지 + 공유 메모리 우체통) | 32/64비트 `Declare` 모두 |
| `CoHunsuJson.bas` | 응답 JSON 만들기 | 새로 짜지 않고 `clockout-vendor-data`를 부른다 |
| `CoHunsuQ_<이름>.bas` | 조회 하나에 파일 하나 | 읽기 전용, 한도(5장) 준수. 안의 함수 이름은 모듈 이름과 달라야 한다(`Query_<이름>`; 같으면 컴파일 오류, 0단계 확인) |
| `CoHunsuDo_<이름>.bas` | 명령 하나에 파일 하나 | 이동 외 상태 변경 금지 |
| `clockout-hunsu.clockout.json` | `type: library`, `category: 라이브러리`, 선언 | 의존: `clockout-lib`, `clockout-vendor-data` |

## 3. 틀이 다리를 부르는 법
- 엑셀 실행 중인 인스턴스마다 다리가 따로 로드된다(칼퇴가 추가기능을 켤 때 로드). 틀은 엑셀 인스턴스를 찾아(창 `EXCEL7` 계열에서 `Application` 얻기) 각각과 통신한다. 다리가 없는 인스턴스는 `bridge_missing`으로 보고 조용히 건너뛴다.
- 호출: `Application.Run("clockout-hunsu.xlam!CoHunsu_Hello" | "CoHunsu_Query" | "CoHunsu_Do", ...)`. 인자와 반환은 모두 문자열(JSON)이다.
  - `CoHunsu_Hello() As String` → 판, `proto`, 지원하는 조회·명령 이름.
  - `CoHunsu_Query(name As String, argsJson As String) As String`
  - `CoHunsu_Do(name As String, argsJson As String) As String`
- 엑셀이 셀을 편집 중이거나 대화상자가 떠 있으면 호출이 거절된다(`RPC_E_CALL_REJECTED` 등). 틀은 `IMessageFilter`로 짧게(50ms 간격, 최대 5회) 다시 시도하고, 그래도 안 되면 `excel_busy`로 보고 마지막 내용을 흐리게 유지한다. 틀의 모든 엑셀 호출은 인스턴스마다 하나인 전용 STA 스레드에서 차례로 한다(구조와 규칙 3.7장 1번). **[0단계 확인]** 거절 코드 종류와 재시도 효과.

**0단계 확인 결과 (2026-11-12, 사무실 PC, 엑셀 16.0 64비트, 보이지 않는 엑셀, `tools/bench`)**
- **매크로가 도는 중(엑셀 바쁨)에는 거절이 오지 않는다.** 호출은 `RPC_E_CALL_REJECTED` 없이 매크로가 끝날 때까지 그대로 기다렸다(1초 매크로 중 hello → 거절 0회, 981ms 뒤 성공). 그래서 틀은 재시도만 믿지 않고, **조회가 250ms를 넘으면 먼저 `excel_busy`처럼 흐리게 표시**하고 끝나면 바로 갱신한다(측정: 바쁨 표시 258ms, 갱신 610ms). 화면 스레드는 그동안에도 바로 반응했다(패널 첫 프레임 0.4ms).
- **엑셀을 막 띄운 직후**에는 호출이 `0x800AC472`(VBA_E_IGNORE)로 거절된다. 이 코드는 메시지 필터를 거치지 않으므로 틀이 직접 같은 정책(50ms, 5회)으로 다시 시도한다(`ExcelStaWorker`).
- **셀 편집 중 거절 코드는 재지 못했다.** 편집 모드는 키보드로만 들어갈 수 있어 사용자 PC 조작 금지 규칙에 걸린다. 사용자가 직접 확인할 항목으로 남긴다(HANDOFF).
- `IMessageFilter.RetryRejectedCall`의 반환값 0~99는 "바로 다시"라서 50ms 간격은 필터 안에서 직접 기다려 만든다.
- 엑셀 COM 호출은 **LCID를 en-US(1033)로** 해야 한다. 고정 문화권(Invariant, LCID 127)으로 부르면 `0x80028018`(TYPE_E_INVDATAREAD)로 실패했다.
- 꺼진 엑셀을 부르면 `0x800706BA`(RPC_S_SERVER_UNAVAILABLE) → `excel_missing`. 앱은 죽지 않고, 새로 띄운 엑셀에는 다음 신호에서 바로 붙었다.
- `Application` 얻기: 보이지 않는 엑셀에서도 `XLMAIN > XLDESK > EXCEL7` + `AccessibleObjectFromWindow`가 됐다(실행 중 개체 표 방법은 예비로만 둠).

## 4. 신호 (다리 → 틀)
**기본은 창 메시지 하나다**(2026-11-12 고침). 신호는 번호와 순번만 알리고, 값은 틀이 `selection.summary` 같은 조회로 받는다. 2번 우체통은 0단계에서 "선택→화면 50ms"를 창 메시지와 조회만으로 못 지킬 때만, 그리고 VBA에서 안전함이 확인될 때만 더한다.
1. **창 메시지**(기본): 틀이 만든 숨은 창(클래스 `ClockOutHunsuMsg`)에 `PostMessage`로 등록 메시지 `ClockOut.Hunsu.Signal`을 보낸다. `PostMessage`는 기다리지 않으므로 엑셀이 느려지지 않는다. `wParam` = 보낸 엑셀 창 핸들(32비트), `lParam` = 신호 번호(8비트) + 순번(8비트).
2. **공유 메모리 우체통**(선택, 실측 뒤 결정): 틀이 만든 이름 있는 공유 메모리(`ClockOutHunsuMail`)에 다리가 고정 길이 기록(64바이트)을 쓴다. 틀은 신호를 받으면 기록을 읽어 선택 주소 같은 짧은 값을 조회 없이 바로 얻는다.

기록 배치(리틀엔디언, 초안): `u32 excelHwnd`, `u16 code`, `u16 seq`, `u32 row`, `u32 col`, `u32 rows`, `u32 cols`, `u32 sheetIndex`, `u32 bookId`(책 세션 번호: 다리가 책이 열릴 때 1부터 매기는 실행 중 번호, 이름·경로 아님), 나머지 예약. 읽는 도중 덮어쓰임은 앞뒤 순번 비교로 걸러 낸다. 기록 64개짜리 고리 버퍼(가장 오래된 것부터 덮어씀). **[0단계 확인]** 공유 메모리를 VBA에서 안전하게 쓸 수 있는지, 안 되면 우체통 없이 "신호는 번호만, 값은 `selection.summary` 조회"로 간다.

**0단계 확인 결과 (2026-11-12): 우체통은 만들지 않는다.** 창 메시지 + 조회만으로 "선택→화면"이 P95 10~12ms(목표 50ms)였다. 구간별 P95: 신호 6~7ms, `light` 조회 4~5ms, 그리기 2ms. 우체통을 더할 이유가 없어 시험하지 않았다.
- 같은 칸을 다시 고르면 엑셀이 선택 이벤트를 내지 않는다(신호가 없다). 정상 동작으로 본다.
- 0단계 최소판은 신호를 묶지 않고(8ms 간격 묶기 없음) 매번 보낸다. 틀이 인스턴스마다 진행 중 조회 하나 + 마지막 신호 하나로 묶는다. VBA에서 8ms 단위 타이머가 마땅치 않아서다.
- 엑셀 두 개를 번갈아 20번 골랐을 때 인스턴스(창 핸들)와 주소가 섞이지 않았다. 다리는 `wParam`에 자기 `Application.Hwnd`를 싣는다. 책 세션 번호(`bookId`)는 우체통이 없어 아직 쓰지 않는다.
- 진단 조회 `bridge.stats`(이벤트 처리 시간 표본, 보낸 신호 수)를 더했다. 측정용이며 모듈은 쓰지 않는다.

| 신호 | 번호 | 언제 | 기록에 실리는 값 |
|---|---|---|---|
| `sel` | 1 | 선택이 바뀜 | 활성 셀 row/col, 선택 크기 rows/cols, sheetIndex |
| `change` | 2 | 값이 바뀜 | 바뀐 영역 row/col/rows/cols, sheetIndex |
| `sheet` | 3 | 시트가 바뀜 | sheetIndex |
| `book` | 4 | 책이 열림, 닫힘, 바뀜 | bookId |
| `calc` | 5 | 계산이 끝남 | 없음 |
| `mode` | 6 | 편집 시작·끝 | col 칸에 0(끝) 또는 1(시작) |

- 같은 종류 신호가 연달아 오면 다리가 묶어서 마지막 것만 보낸다(`sel`은 최소 8ms 간격). 틀도 순번을 보고 낡은 것은 버린다.
- `mode`는 엑셀에 편집 이벤트가 없어 다리가 직접 감지하지 못한다. 틀이 호출 거절로 추정한다. 이 신호는 정확히 지원할 수 없으면 목록에서 뺀다. **[0단계 확인]**

## 5. 조회 (틀 → 다리)
공통: 요청 `argsJson`은 객체, 응답은 `{"ok":true,"proto":0,"data":{...}}` 또는 `{"ok":false,"proto":0,"code":"고정 코드","error":"한국어 문장"}`. 응답은 256KB 이내, 넘으면 `truncated:true`로 자른다. 모든 목록 조회는 `limit`(기본 200, 최대 1000)을 지킨다.

| 이름 | 요청 | 응답 `data` | 무게 |
|---|---|---|---|
| `hello` | 없음 | `version`, `proto`, `queries[]`, `commands[]`, `signals[]`, `office`(버전, 비트) | light |
| `bridge.stats` | `{}` 또는 `{reset:true}` | `events`, `sent`, `target`, `samplesUs[]`(최근 256개) | light, 진단용(0단계에 더함) |
| `selection.summary` | `{}` | `addr`, `sheet`, `book`, `count`, `nonEmpty`, `sum`, `avg`, `min`, `max`, `errors`, `types{num,text,formula}` | light |
| `book.info` | `{}` | `name`, `path`, `saved`, `calcMode`, `sheets`, `protected` | light |
| `sheets` | `{}` | `items[{index,name,visible,tab,active}]` | light |
| `errors` | `{scope:"sheet"\|"book", limit}` | `count`, `items[{addr,sheet,kind,reason,root}]`, `truncated` | normal |
| `precedents` | `{addr, depth, limit}` | `nodes[{id,addr,sheet,formula,isError,isRoot}]`, `edges[{from,to}]`, `truncated` | heavy |
| `dependents` | `{addr, depth, limit}` | `precedents`와 같은 모양(이 셀을 쓰는 셀들. 바꾸면 어디가 영향받는지) | heavy |

- 오류 `kind`: `ref`, `div0`, `value`, `na`, `name`, `null`, `num`, `spill`, `calc`(엑셀 오류 값 그대로). `reason`은 다리가 알 수 있는 짧은 한국어 설명(예: "참조가 지워진 셀을 가리킴").
- `errors.root`는 그 오류가 시작된 셀 주소(오류를 만든 입력이 오류가 아닌 셀)다. 찾기는 `DirectPrecedents` 따라가기로 하고 깊이와 개수 한도를 지킨다.
- `precedents`는 `DirectPrecedents`, `dependents`는 `DirectDependents`로 모은다(둘 다 같은 시트 안만 돌려주는 한계가 있어 다른 시트 참조는 수식 글자를 읽어 보탠다 **[0단계 확인]**). 다른 책이나 다른 시트로 이어지는 선은 `sheet`/`book`을 적고, 닫힌 책이면 `external:true`로 표시만 한다.
- **구현 현황 (2026-11-12 밤, 다리 0.0.011, 아직 PC에서 컴파일·실행 전)**: `errors`는 활성 시트만(요청의 `scope`·`limit` 미지원, 최대 100개), 항목은 `{addr, sheet, kind, label, formula}`이고 `count`가 전체 수다(`reason`, `root`는 다음 단계). `sheets`는 보이는 시트만 `{index, name, visible:true, active}`(`tab` 색은 다음 단계). 둘 다 `book`·`active`·`sheet` 이름을 data에 함께 싣는다.
- **새 조회 `flow.neighbors`** (가벼운 이웃 보기, 위 `precedents`/`dependents` 그래프와 별개): 요청 `{}`. 응답 `sheet`, `addr`, `formula`, `hasFormula`, `value`, `crossSheet`, `precedents{count, items[{addr,value}], truncated}`, `dependents{...}`. 활성 셀 기준, `DirectPrecedents`/`DirectDependents`라 같은 시트만, 항목은 영역마다 하나(최대 20). 무게 normal.
- **새 조회 `book.info`**: `name`, `saved`, `readOnly`, `calcMode`(auto|manual|semi), `sheets`, `activeSheet`, `structureProtected`(경로는 돌려주지 않음). **`book.audit`**: `hidden`, `veryHidden`, `protectedSheets`, `links`, `names`, `hiddenList[{name,kind}]`, `truncated`. **`names`**: `count`, `items[{name,sheet,addr,where}]`(최대 100, 칸을 가리키지 않는 이름은 sheet·addr가 빈 글자), `truncated`. 모두 읽기 전용, 무게 light~normal.
- 새 조회는 이름을 더하고 이 표에도 더한다. 이름과 뜻은 바꾸지 않는다.

## 6. 명령 (틀 → 다리)
| 이름 | 요청 | 하는 일 |
|---|---|---|
| `goto` | `{addr, sheet?, book?}` | 해당 셀로 이동(필요하면 시트·책 활성화). 선택 영역이 바뀐다 |
| `sheet.activate` | `{name}` 또는 `{index}` | 시트를 활성화 |

- **구현 현황 (2026-11-12 밤)**: `goto`는 `{addr, sheet?}`(`book`은 아직 없음, 시트를 먼저 활성화한 뒤 `Application.Goto`로 스크롤하며 이동), `sheet.activate`는 `{name}`만. 실패하면 `code:"command_failed"`(셀 편집 중 등). 틀은 모듈 선언의 `commands`에 없는 명령은 보내지 않는다.
- 명령도 읽기 전용 원칙의 예외는 "선택과 활성 시트 이동" 뿐이다. 이동은 실행 취소 기록을 지우지 않는다.
- 응답: `{"ok":true,"proto":0,"data":{}}`. 보호된 시트나 숨은 시트는 `code: "sheet_unavailable"`.

## 7. 오류 코드 (다리 쪽)
구조와 규칙 7.4장의 표를 따른다. 다리가 더하는 코드: `args_bad`(요청 형식이 틀림), `limit_exceeded`(한도 초과로 잘림, 오류가 아니라 `truncated`로 알림), `sheet_unavailable`, `range_bad`(주소를 읽을 수 없음), `protected_view`(보호된 보기에서는 이벤트와 조회가 막힘 — 틀은 쉼 상태로 표시).

## 8. 판과 호환
- `proto`는 통신 형식 번호(지금 0). 틀은 `hello`로 받은 `proto`가 자기보다 높으면 쓰지 않고 업데이트를 안내하고, 한 단계 낮으면 받아 준다.
- 다리의 판(`vX.Y.Z`)은 모듈이 선언한 `min_version`과 비교해 `bridge_old`를 결정한다.
- 조회와 명령을 더하면 Y를 올리지 않아도 되지만(+100) `hello`의 목록에 나타나야 한다. 모듈은 필요한 조회가 목록에 없으면 `query_unknown`으로 그 모듈만 쉰다.

## 9. 만들 때의 약속
- VBA 소스는 CP949+CRLF(칼퇴 규칙). `Declare`는 `#If VBA7 Then ... PtrSafe` 두 갈래를 모두 쓴다.
- 지역 변수 이름에 예약어와 겹치는 말(`name`, `out`, `scale` 등)을 쓰지 않는다.
