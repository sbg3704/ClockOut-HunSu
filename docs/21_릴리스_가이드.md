# 훈수꾼 릴리스 가이드 (2026-11-17)

훈수꾼 새 판을 칼퇴 레일로 내보내는 순서입니다. 코드는 클라우드에서 못 빌드하므로 빌드·Release는 사용자 PC에서 합니다. Claude가 하는 것은 판 번호 올리기와 catalog.json 수정 PR까지입니다.

## 한눈에 보기
1. 판 번호 올리고 PR 머지 (훈수꾼 저장소)
2. PC에서 묶음 만들기: `pwsh -File tools\pack_app.ps1 -Version X.Y.ZZZ`
3. Release 올리기: 태그 `app-hunsu-X.Y.ZZZ`, 파일 `hunsu.zip`
4. 카탈로그 `catalog.json`의 훈수꾼 항목 고치고 머지
5. 칼퇴에서 받아 확인

## 1. 판 번호
- 한 곳만 고칩니다: 훈수꾼 저장소 `Directory.Build.props`의 `<Version>` (형식 `X.Y.ZZZ`, 끝 세 자리).
- 무게: 고침 +1, 새 기능 덩어리 +10, 구조 변경 +100.
- 프로그램(`src/`, `modules/`, `addins/`)을 바꾼 PR은 올려야 합니다. `tools\check_version.ps1`이 빌드 때 검사합니다.
- 패치노트 `assets\guide\hunsu.changes.md` 맨 위를 `## vX.Y.ZZZ (날짜)`로 새로 쓰고 `hunsu.guide.md`도 맞춥니다. 안 맞으면 5단계 포장이 실패합니다.
- 올린 판을 main에 머지한 뒤 그 main에서 빌드합니다.

## 2. 빌드와 묶음 (사용자 PC)
- 저장소: `D:\CO\ClockOut-HunSu`. 먼저 `git pull`로 main을 받습니다. 엑셀이 설치돼 있어야 하고 PowerShell 7(`pwsh`)이 필요합니다.
- 전체 시험(선택): `pwsh -File tools\build.ps1 -Release`
- 묶음: `pwsh -File tools\pack_app.ps1 -Version 0.0.201`
  - 판 번호는 `Directory.Build.props`와 같게 씁니다.
  - 엑셀 없이 이미 만든 `out\clockout-hunsu.xlam`을 쓰려면 `-SkipBridge`.
- 결과는 `out\pack\` 아래에 생깁니다.
  - `hunsu.zip` (묶음, 약 75MB)
  - `hunsu.zip.sha256` (해시)
  - `catalog-entry.json` (카탈로그에 넣을 항목, 해시와 크기가 이미 들어 있음)
- 끝에 안내문 검사(`check_guide.ps1`)가 자동으로 돌고, 어기면 zip이 지워지며 실패합니다.
- 주의: 같은 판 번호로 다시 빌드하면 zip이 달라져 해시도 바뀝니다. Release에 올린 뒤에는 그 파일의 해시를 기준으로 합니다.

## 3. Release 올리기 (사용자가 직접)
공개 저장소 `sbg3704/ClockOut-Catalog`에 올립니다. 태그는 `app-hunsu-<판>`입니다(추가기능 태그, 칼퇴 앱 태그 `app-v<판>`과 겹치지 않게).

```
gh release create app-hunsu-0.0.201 D:\CO\ClockOut-HunSu\out\pack\hunsu.zip --repo sbg3704/ClockOut-Catalog --title "훈수꾼 0.0.201" --notes "패치노트 내용" --latest=false
```

- `--latest=false`는 필수입니다(칼퇴 앱 릴리스를 최신으로 두기 위해).
- 웹에서 하려면 Releases → Draft a new release → 태그 `app-hunsu-0.0.201` 새로 만들기 → `hunsu.zip` 끌어 놓기 → Set as the latest release 체크 해제.
- 올린 뒤 파일 주소가 `https://github.com/sbg3704/ClockOut-Catalog/releases/download/app-hunsu-0.0.201/hunsu.zip`인지 확인합니다.

## 4. 카탈로그 수정
`ClockOut-Catalog`의 `catalog.json` → `apps` 구역 훈수꾼 항목에서 아래 5곳만 바꿉니다. 값은 `out\pack\catalog-entry.json`에서 그대로 옮깁니다.

| 칸 | 값 |
|---|---|
| `version` | 판 번호 |
| `url` | 위 Release 파일 주소 (`app-hunsu-<판>`) |
| `sha256` | `hunsu.zip.sha256`의 앞 64자 |
| `size` | `hunsu.zip` 바이트 수 |
| 맨 위 `updated` | 오늘 날짜 |

- `spec`은 0 그대로 둡니다(올리면 옛 칼퇴의 찾기 탭이 막힘).
- `summary`는 `catalog-entry.json`의 것이 아니라 카탈로그에 이미 있는 문구(현재 "[시험 기능 · 테스트 중] …")를 유지합니다.
- 새 판은 칼퇴가 같은 id의 새 판으로 알아봅니다. 칼퇴는 받은 파일의 SHA-256이 같을 때만 설치합니다.
- 순서 권장: Release를 먼저 올리고 나서 카탈로그를 머지합니다. 반대로 하면 그 사이에 [받기]가 404가 납니다. 이번 0.0.201은 사용자 요청으로 카탈로그를 먼저 머지했으므로 Release를 바로 올려야 합니다.

## 4-1. SHA 장부 (2026-11-22)
- Release에 올린 `hunsu.zip`을 받아 SHA-256을 다시 계산해 `hunsu.zip.sha256`과 같은지 본다.
- 같으면 `out\pack\release-record.json`의 `ledgerRow` 한 줄을 `releases/hunsu_sha256.md` 표 맨 위에 더한다(카탈로그 PR과 같은 때). 서버 비공개 장부도 같은 값을 쓴다.
- 한 판 = 한 SHA. 다시 만들어야 하면 판을 올린다(`pack_app.ps1`이 장부와 다른 SHA를 막는다). 규칙은 `docs/22` 7장.

## 5. 확인
- 칼퇴 좌측 레일에서 훈수꾼을 열어 새 판이 보이는지, [받기] → 설치 → 켜기가 되는지 봅니다.
- 소개 화면의 사용법·패치노트가 새 판 것인지 봅니다.
- 문제가 있으면 카탈로그 항목을 이전 판(version·url·sha256·size 세트)으로 되돌립니다. Release 파일은 지우지 않아도 됩니다.

## 자주 틀리는 것
- 해시나 크기를 다른 판 것과 섞어 씀 → 칼퇴가 설치를 거부합니다. 항상 한 번 빌드한 한 세트를 씁니다.
- 판 번호를 안 올림 → 빌드가 실패합니다.
- 패치노트 맨 위 판이 다름 → 포장이 실패합니다.
- Release 태그를 `app-v…`로 씀 → 칼퇴 앱 릴리스와 섞입니다. 반드시 `app-hunsu-…`.
- 코드 서명이 없어 SmartScreen 경고가 날 수 있습니다(결정 2026-11-09).
