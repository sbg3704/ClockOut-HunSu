## 0. 배경 (1분 요약)
- **칼퇴**는 엑셀 추가기능(VBA) 관리 프로그램(C# .NET 8 WinForms)이다. **훈수꾼**은 그 하위 프로그램으로, 엑셀 창 위에 오류 난 셀, 수식 순서도, 시트 이동 같은 정보를 겹쳐 보여 주는 오버레이다.
- 구조 세 층: 엑셀 안의 **VBA 다리**(`clockout-hunsu`), 칼퇴 쪽에서 도는 **WPF 틀**(오버레이 창, 자리, 패널), JSON으로 선언하는 **모듈**. 화면은 WPF 네이티브(WebView2 쓰지 않음), 반응성이 최우선이다.
- 기획은 끝났고 결정은 문서에 있다. 이번에는 구현을 시작한다. 클라우드에는 엑셀과 Windows가 없으므로 **엑셀이 필요한 일은 PC에서(Remote Control)** 해야 한다.

## 1. 저장소 연결 (가장 먼저)
연결할 저장소 세 개:
| 저장소 | 공개 | 용도 | 필요한 권한 |
|---|---|---|---|
| `sbg3704/ClockOut-HunSu` | 사용자 확인 | 훈수꾼 문서, 틀, 다리, 모듈 | 푸시, PR |
| `sbg3704/ClockOut-Catalog` | 공개 | 추가기능 소스, `catalog.json`, Release, 빌드 도구 | 푸시, PR |
| `sbg3704/ClockOut` | 비공개 | 칼퇴 매니저 앱(C#), 규칙 문서 | 푸시, PR |

1. 세션에 저장소가 없으면 `add_repo`(owner `sbg3704`, 저장소 이름, `access: push`)로 붙인다. 거절되면 이유를 사용자에게 그대로 전하고(설정 링크 포함) 연결된 저장소 안에서 할 수 있는 일부터 한다.
2. 클론은 **한 번에 하나씩**, 얕게(`git clone --depth 1`), 넉넉한 시간 제한(10분)으로 한다. 같은 저장소에 동시에 두 번 접근하면 429가 난다. 클론한 뒤에는 `register_repo_root`로 알린다.
3. GitHub 작업은 `gh`가 아니라 GitHub MCP 도구(`mcp__github__*`)를 쓴다. 검색만 `gh api search/...`.
4. **PC에서 작업(엑셀 필요)할 때**: Remote Control로 사용자 PC에서 한다. 폴더는 집 PC `G:\ClockOut`, 사무실 PC `D:\CO\ClockOut`, `D:\CO\ClockOut-Catalog` 아래다. 지금 어느 PC가 켜져 있는지 `list_devices`로 확인하고, 훈수꾼 저장소가 PC에 없으면 같은 위치에 `ClockOut-HunSu` 폴더로 클론한다(`git clone https://github.com/sbg3704/ClockOut-HunSu`).
5. **사용자 PC에서 키보드 입력, SendKeys, 화면 조작은 금지**다. 엑셀은 보이지 않는 인스턴스(`Visible=False`)와 COM으로만 다룬다. 엑셀이 갑자기 여러 번 켜지면 즉시 멈춘다.

- 계정1(다른 Claude)은 `ClockOut-HunSu`의 `src/`(C# 틀, `Core`, `Ui`, 시험)와 `docs/01`, `docs/03`, `docs/04`를 맡는다. **그 파일은 고치지 않는다.** 고칠 일이 보이면 PR 본문 ③에 요청으로 적는다.
- 네가 맡는 파일: `ClockOut-HunSu`의 `addins/clockout-hunsu/`, `tools/test_bridge.ps1`, `docs/02_다리_규격.md`(확인 결과 반영만), 그리고 `ClockOut`·`ClockOut-Catalog` 쪽 아래 일들.
- 일 번호는 계정1이 1~199, **너는 201부터** 쓴다(충돌 방지). 브랜치: `claude/h-<세부>-<일번호>-<슬러그>`(ClockOut 저장소는 `claude/a-...`, Catalog는 `claude/i-...` 규칙을 따른다). 모든 일은 최신 `main` 위 새 브랜치에서 하고, `main`에 직접 푸시하지 않는다.

## 4. 맡을 일 (우선순위 순서)

### A. 다리 최소판과 0단계 확인 (최우선, PC와 엑셀 필요)
`docs/02_다리_규격.md`를 구현한다. 위치 `ClockOut-HunSu/addins/clockout-hunsu/`.
1. 파일: `CoHunsuApi.cls`, `CoHunsuEntry.bas`, `CoHunsuEvents.cls`, `CoHunsuMail.bas`, `CoHunsuJson.bas`(JSON은 `clockout-vendor-data`의 `JsonConverter`를 쓰고 새로 짜지 않는다), `CoHunsuQ_*.bas`, `CoHunsuDo_*.bas`, 선언 `clockout-hunsu.clockout.json`(`type: library`, 의존 `clockout-lib`, `clockout-vendor-data`).
2. 구현 범위(이번에는 최소): `Hello`, `Query`(`selection.summary`, `book.info`, `sheets`), `Do`(`goto`, `sheet.activate`), 신호 `sel`, `sheet`, `book`. `errors`와 `precedents`는 다음 일로 남긴다(PR ③에 적는다).
3. **0단계 확인 항목을 실제 엑셀에서 재서 `docs/02`의 [0단계 확인] 표시를 결과로 바꾼다.** 이것이 이 일의 핵심 산출물이다:
   - 공유 메모리 우체통(`OpenFileMapping`/`MapViewOfFile`)을 VBA(32/64비트)에서 안전하게 쓸 수 있는가. 안 되면 대안(번호만 보내고 값은 `selection.summary` 조회)으로 문서를 고친다.
   - 셀을 편집 중일 때 `Application.Run` 호출이 거절되는 코드(`RPC_E_CALL_REJECTED` 등)와 재시도 효과.
   - 편집 시작·끝(`mode` 신호)을 다리가 감지할 수 있는가(없으면 목록에서 뺀다고 문서에 적는다).
   - 엑셀 두 개 동시, 엑셀 재시작에서 다리가 끊기지 않는가.
   - 이벤트 한 번의 다리 처리 시간(목표 5ms), `light` 조회 왕복(목표 20ms).
4. `tools/test_bridge.ps1`: 보이지 않는 엑셀에서 COM으로 다리를 불러 JSON을 검증하는 시험 스크립트.
5. 빌드: VBA 소스는 CP949+CRLF(`ClockOut-Catalog/tools/vba_encode.py`), 컴파일 확인은 보이지 않는 엑셀에서 VBE 컴파일 명령(`CommandBars` Id 578)이 비활성이 되는지로 판정한다(매크로를 돌려 보는 것은 컴파일 검증이 아니다). 빌드 도구는 `ClockOut-Catalog/tools/build_addin.ps1`을 부르거나, 안 되면 `ClockOut-HunSu/tools/`에 임시로 복사하고 **PR 본문에 "Catalog로 통합할 일"로 적는다**.
6. 주의: 지역 변수 이름에 `name`, `out`, `scale`, `inStr`, `base`, `w`, `h` 같은 예약어나 내장 함수와 겹치는 말을 쓰지 않는다(한글판 엑셀 컴파일 오류가 실제로 났다). 범용 함수는 `clockout-lib`에 더하고 다리는 부른다(함수 중복 선언 금지). 파일은 300줄 안팎. `Declare`는 `#If VBA7 Then ... PtrSafe` 두 갈래.
7. 완료 기준: PR에 확인 결과 표(위 5개), 컴파일 확인 결과, `test_bridge.ps1` 실행 결과.

### B. 카탈로그 `apps` 구역 규격 (ClockOut-Catalog + ClockOut)
칼퇴 좌측 레일이 읽을 "하위 프로그램 목록"을 `catalog.json`에 더한다.
1. `catalog.json` 최상위에 `apps` 배열을 더한다. 항목: `id`, `name`, `version`, `icon`(작은 PNG/SVG 주소 또는 내장 이름), `summary`(한 줄), `description`, `preview`(그림 주소, 선택), `url`, `sha256`, `size`, `requires`(`{"excel":"2016","clockout":"0.1.100"}` 형식), `host`.
2. **하위 호환이 최우선**: 지금 배포된 칼퇴 앱(v0.1.000)은 `apps`를 몰라도 `catalog.json`을 읽을 수 있어야 한다. `spec` 값을 올릴지(올리면 옛 앱이 거부하는지) `ClockOut`의 카탈로그 읽기 코드(`app/ClockOut.Core/Catalog`)를 읽고 확인한 뒤, 결론과 근거를 PR에 적는다. 새 구역은 `spec`을 올리지 않고 더하는 쪽을 먼저 검토한다.
3. 목록을 읽는 Core 코드(순수 계산)와 시험을 `ClockOut`의 `ClockOut.Core`에 더한다(`apps` 모델, 읽기, 잘못된 항목만 건너뛰고 이유 기록 — 기존 추가기능 읽기 방식과 같게).
4. `ClockOut/docs/03_매크로_제작_가이드.md`의 카탈로그 규격 부분과 `Catalog/README.md`를 갱신한다.
5. `tools/publish_hunsu.ps1`(틀 zip을 Release로 올리고 `apps` 항목 등록)는 **스크립트 초안만** 쓴다. 공개 Release 생성은 사용자가 PC에서 직접 한다(권한 검사가 막는다).

### C. 칼퇴 좌측 레일 (ClockOut 저장소, WinForms) — 크니까 PR 셋으로 나눈다
시안(위 링크)을 그대로 구현한다. 기존 UI 규칙(`UiTheme`, `UiFonts`, `UiScale`, 8px 격자, 깜빡임 방지 `BufferedPanels`)을 따르고 `docs/06_UI_사용성_점검표.md`를 지난다.
- **C1(순수 계산)**: 하위 프로그램 상태 계산 `새로 올라옴 / 받을 수 있음 / 받는 중 / 켜짐 / 꺼짐 / 업데이트 있음`, 레일 항목 순서(카탈로그 순서 + 사용자 순서 저장), "새로 올라옴" 판정(이미 본 목록 기억). `Core`에 두고 시험을 쓴다.
- **C2(레일 화면)**: 64px 레일, `»`로 196px 펼침(기억), 아이콘 5상태 표시, 선택 표시, 툴팁, 맨 위 칼퇴 + 구분선 아래 하위 프로그램. 기존 `MainForm`에 모든 걸 넣지 않고 컨트롤을 나눈다. 폭 64px에서 깜빡임과 글꼴 배율(DPI 100~200%)을 확인한다.
- **C3(소개 화면과 받기·설치)**: 소개 화면(받기 전, 받는 중, 설치됨, 업데이트), 받기와 설치는 **기존 추가기능 안전 규칙을 재사용**한다(SHA-256 확인, 임시 이름에 받아 원자적 교체, 실패하면 되돌리기, 작업 기록, `CatalogDownloads`). 하위 프로그램 실행·종료는 칼퇴가 맡는다(시작 때 같이 켜기 설정).
- 화면 스크린샷은 기존 `tools/screenshots` 도구로 찍어 PR에 붙인다(사용자 PC 조작 없이).

### D. `ClockOut.Core` NuGet 내보내기 준비 (ClockOut) — 낮은 우선순위
훈수꾼이 `ClockOut.Core`를 NuGet 패키지로 받아 쓰려 한다. `ClockOut.Core.csproj`를 패키지로 내보낼 수 있게(`IsPackable`, 패키지 ID와 판, 설명, 라이선스 표기 없음 유지) 하고, 로컬 피드(`out/nuget`)에 만드는 `tools/pack-core.ps1`과 사용법(`docs/`)을 쓴다. 엑셀 연결 코드(`adapters/excel`)도 같이 쓸 수 있는지 확인해 결과를 PR에 적는다. 안 되면 하위 모듈로 연결하는 대안을 제안한다.

### E. 오픈소스 후보 확인표 (ClockOut-HunSu, 문서만)
`docs/01` 3.5장 후보 표(WPF-UI, MaterialDesignInXaml, HandyControl, CsWin32, SkiaSharp, Lottie, MSAGL, Fluent UI System Icons, 글꼴)를 **실제로 확인**해서 `vendor/SOURCES.md` 표를 채운다: 최신 안정판, 라이선스(허용형만, GPL 계열과 상용 겸용 제외), 관리 상태(마지막 릴리스 날짜), .NET 8과 Windows 10 호환, 크기. 판은 특별한 이슈가 없으면 최신으로 한다. 실제 패키지 복원은 `src/`가 생긴 뒤 계정1이 하므로 **표만** 만든다. (`vendor/` 폴더와 `SOURCES.md`는 이 일로 네가 만든다.)

## 5. 규칙 (어기지 않는다)
1. **PR 본문은 `ClockOut-HunSu/.github/pull_request_template.md`의 여섯 항목**(① 무엇을 왜 ② 끝난 것 ③ 남은 일과 다음 할 일 ④ 확인한 범위와 못 한 것 ⑤ 관련 결정(문서 장 번호) ⑥ 먼저 읽을 파일 3개)을 모두 채운다. 다른 저장소 PR도 같은 여섯 항목으로 쓴다. PR 본문 맨 위에는 프로젝트가 요구하는 attribution 블록을 넣는다.
2. 커밋 제목은 무엇을 했는지, 본문은 왜 그렇게 했는지와 버린 대안. 한 커밋은 한 가지 일.
3. 일이 끝나거나 멈출 때 해당 저장소의 `HANDOFF.md`를 갱신한다(지금 상태, 다음 할 일, 막힌 것).
4. 사용자가 정한 것은 `docs/`에 날짜와 장 번호로 남긴다. 규칙이 바뀌면 코드보다 문서를 먼저 고친다.
5. 코드 규칙: 모든 소스 맨 위에 한국어 주석(기능, 사용법, 의존), 파일 하나는 한 가지 책임(권장 300줄, 800줄 넘기지 않음), 순수 계산은 화면과 엑셀 없이 시험되게 분리, 새 기능은 새 파일로.
6. **같은 코드를 두 번 짜지 않는다.** 먼저 `clockout-lib`, `ClockOut.Core`, 받아 둔 오픈소스에 있는지 찾고, 없으면 공용에 먼저 더한 뒤 가져다 쓴다. 오픈소스는 허용형 라이선스만, 판을 고정하고 `SOURCES.md`에 적는다.
7. 판 번호(`vX.Y.Z`)는 작업 중에 매기지 않는다. PR 본문에 무게(+1, +10, +100)만 적는다.
8. 비밀값(토큰, 키)은 어디에도 적지 않는다. 회사 자료는 저장소에 넣지 않는다. 바이너리(`.xlam`, exe, zip)는 커밋하지 않고 Release로 올린다(Release 생성은 사용자가 PC에서 직접).
9. 클라우드에서 확인한 것과 PC에서 확인해야 할 것을 PR ④에 나눠 적는다. 확인하지 않은 것을 확인했다고 쓰지 않는다. 도구 호출이 실패했는데 성공했다고 보고하지 않는다.
10. 사용자에게 보내는 말은 한국어, 결론부터, 짧게. 결정이 필요하면 선택형 카드로 하나씩 묻는다. 위트 있는 이름과 세련된 디자인을 좋아한다.

## 6. 진행과 보고
- 순서: A → B → C1 → C2 → C3 → D → E. A가 PC 사정으로 막히면 먼저 B, E를 진행하고 A는 사유를 적어 둔다.
- 일 하나가 끝날 때마다 PR을 열고(어시스턴트 지정과 리뷰 요청 규칙은 프로젝트 지시를 따른다) 저장소 `HANDOFF.md`를 갱신한다. 사용자에게는 PR이 열렸을 때와 사용자 결정이 필요할 때만 알린다.
- 마지막에 PR 링크 목록, 끝난 것, 남은 일, 막힌 것을 한 번에 정리해 보고한다.
- 막히면(권한, 저장소 접근, PC 연결) 이유를 그대로 전하고 할 수 있는 다른 일로 넘어간다. 같은 시도를 반복하지 않는다.
