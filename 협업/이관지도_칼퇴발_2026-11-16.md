# 엑셀 추가기능 → 훈수꾼 이관 지도 (무엇을 옮길 수 있고, 무엇을 엑셀에 남기나)

(칼퇴 쪽이 사용자(설계로)를 통해 훈수꾼 프로젝트에 넘긴 쪽지 원문을 그대로 저장한 것이다. 훈수꾼 쪽 대조와 결정은 `docs/11_엑셀_추가기능_이관.md`.)

이 쪽지 하나만 읽어도 이해되게 썼다. 사용자(설계로)가 이 정리를 훈수꾼 프로젝트에 넘겨 **훈수꾼에 이미 있는 것과 대조한 뒤 작업**하려는 것이 쓰임이다. 칼퇴 쪽은 코드를 고치지 않았고, 아래는 전부 `sbg3704/ClockOut-Catalog` 소스를 읽고 정리한 것이다.

## 0. 결론 먼저
1. **방향(사용자 결정, 2026-11-16)**: 엑셀 추가기능은 더 키우지 않고, 새 기능은 훈수꾼에 넣는다. 칼퇴는 훈수꾼 같은 프로그램과 라이브러리의 설치·관리 도구로 둔다. 기존 추가기능은 당분간 그대로 두고(고장 수리만), 옮길 수 있는 것부터 하나씩 옮긴다.
2. 추가기능 10개(명령 38개) 가운데 **엑셀 안에 꼭 남겨야 하는 것은 2개뿐**이다: `visible-copy`(복사·붙여넣기 가로채기), `image-fit`(붙여넣기 키 가로채기 + 그림). 나머지 8개는 옮길 수 있다.
3. 하지만 **걸림돌이 하나 있다. 훈수꾼 다리는 지금 읽기와 이동만 한다**(docs/01 9장 8번 "셀 값을 바꾸지 않는다"). 옮길 대상의 대부분(약 30개 명령)은 셀을 **바꾸는** 도구다. 이관하려면 이 원칙에 "확인을 받는 쓰기 명령"이라는 예외를 새로 정해야 한다(4장). **이건 사용자가 정할 일**이라 이 쪽지는 정하지 않고 선택지와 칼퇴 쪽 의견만 둔다.
4. 읽기·표시만 하는 것(선택 요약, 십자 음영, 색깔별 합계, 폴더 파일 목록)은 바로 옮길 수 있다. 그중 **선택 요약은 훈수꾼에 이미 있다**(5장).
5. 추가기능 중 워크시트 함수(UDF)와 리본 탭을 쓰는 것은 **하나도 없다**. 엑셀 안에서만 되는 것은 `OnKey` 단축키, 셀·시트 우클릭 메뉴, 클립보드·붙여넣기 가로채기, 파일에 남는 서식 규칙 정도다.

## 1. 배경 (훈수꾼 프로젝트가 모를 수 있는 것)
- **칼퇴(ClockOut, `sbg3704/ClockOut`)**: 엑셀 추가기능(.xlam, VBA)을 찾고 설치·업데이트하는 Windows 앱. 목록은 `sbg3704/ClockOut-Catalog`의 `catalog.json`(`addins`, `libraries`, `apps` 구역)이고 파일은 GitHub Release에 올린다.
- 추가기능은 모두 같은 틀이다. 선언 파일 `<id>.clockout.json`(명령 `commands`, 설정 `params`, 의존 `dependencies`) + `.bas` 모듈 + `ThisWorkbook_코드.txt`(열 때 시작·닫을 때 해제). **공용 VBA 라이브러리 `clockout-lib`**(`addins/_common`, `CoText`·`CoNum`·`CoRange`·`CoGuard`·`CoFile`·`CoShape`·`CoKey` 등)에 의존한다. 외부 공개 VBA는 4묶음(`clockout-vendor-array|data|sys|text`).
- 도구 호출 방식은 둘뿐이다. ① 셀 우클릭(`CommandBars("Cell")`)·시트 탭 우클릭(`CommandBars("Ply")`)에 "칼퇴 …" 메뉴를 만든다. ② 설정한 단축키를 `Application.OnKey`로 건다(기본은 대부분 비어 있음, `image-fit`만 `^+A`, `^+V` 기본값).
- 값을 바꾸는 도구는 모두 "N칸이 바뀝니다" 확인을 받고 실행하며, VBA 한계로 **Ctrl+Z로 되돌릴 수 없다**고 안내한다.

## 3. 추가기능별 분류 (10개, 명령 38개)
`<명령 라벨> <매크로 이름>` 형식. "필요한 것"은 훈수꾼 쪽에서 새로 있어야 하는 것이다.

### 3-1. `selection-stats` 선택 요약 크게 보기: **D**
- 하는 일: 상태 표시줄의 합계·평균·개수를 큰 글씨 떠 있는 창에 표시(`SelStats_Toggle` 1개). 설정: 글자 크기, 천 단위 쉼표, 숫자 개수·최소·최대 보기, 시작 때 자동 열기.
- 훈수꾼: **`hunsu-selection` 모듈이 이미 같은 일을 한다**(합계·평균·최소·최대·개수·오류·종류별 칸 수, 핀 창으로 띄울 수 있음).
- 대조할 것: ① 추가기능은 **숨긴 줄(필터로 가려진 줄 포함)과 오류 칸을 세지 않는다**고 정해 두었다(README "규칙"). 훈수꾼 `selection.summary`(`CoHunsuQ_SelectionSummary.bas`)는 코드에서 숨긴 줄을 빼는 처리가 보이지 않는다. 같은 뜻으로 맞출지 정할 것. ② 글자 크기·쉼표 설정이 훈수꾼에 있는지.
- 결론: 이관 작업 없음. 위 두 가지만 맞추면 추가기능을 카탈로그에서 내려도 된다.

### 3-2. `cross-hair` 십자 음영: **A (표시층으로 이관, 이점이 큼)**
- 하는 일: 선택 칸의 행·열을 연한 색으로 표시(`CrossHair_Toggle`). 구현: 시트 전체에 **조건부 서식**을 걸고 `CELL("row")` 수식으로 현재 위치를 읽게 한다. 저장·닫기 직전에 규칙을 지운다.
- 왜 옮기면 좋은가(추가기능의 약점을 훈수꾼이 없앤다): 조건부 서식을 거는 순간 **실행 취소 기록이 지워지고**(README에 적힘), 보호된 시트에는 못 걸고, 칸 배경색을 덮고(반투명 불가), 계산이 많은 시트에서 클릭마다 재계산 비용이 든다. 훈수꾼 표시층(오버레이)은 이 넷이 모두 없다.
- 훈수꾼에 있는 것: `hunsu-marks`(조회 `mark`가 보이는 칸의 화면 좌표를 주고 앱이 엑셀 위 투명 창에 그림). 지금은 오류 칸 테두리·수식 이웃 표시뿐이고 **"선택 칸의 행·열 띠"는 없다**.
- 필요한 것: `mark` 조회에 활성 칸의 행 띠·열 띠 영역을 돌려주는 종류 추가(또는 앱이 `panes` 격자로 계산), `marks[]`에 반투명 칠 `style`. 설정(표시 방식 선/음영, 색 3개, 행·열 켜기, 시작 때 자동 켜기)은 모듈 `params`로.
- 위험: 훈수꾼 표시층은 스크롤을 이벤트가 아니라 400ms 폴링으로 따라간다(`markPollMs`, `docs/08`). 십자선은 스크롤하는 동안 어긋나 보이면 바로 눈에 띈다. 또 확대 배율·모니터 배율에서 칸 위치가 맞는지 아직 아무도 눈으로 보지 못했다(HANDOFF 2026-11-16). 이 둘이 확인되기 전에 추가기능을 내리지 말 것.

### 3-7. `book-tools` 통합 문서 도구: 명령 8개 (전부 **B**)
- 숨은 시트 모두 보이기 / 선택한 시트만 남기고 숨기기 / 시트 탭 이름순 정렬 / 시트 이름 일괄 바꾸기 / 공유 전 정리(모든 시트 A1·맨 위·배율 100%) / 원클릭 백업 / 선택 시트를 PDF 하나로 / 입력 칸 비우기(상수만 지우고 수식·서식 유지).
- 짝이 되는 훈수꾼 모듈: `hunsu-audit`(숨은 시트 수 표시), `hunsu-sheets`(시트 목록). **"보여 주는" 모듈 옆에 "고치는" 단추 하나**가 붙는 모양이 가장 자연스럽다(예: 책 점검 패널의 "숨은 시트 N개" 옆에 [모두 보이기]).
- 새 조회가 필요: Ctrl로 **여러 시트 탭을 고른 상태**(`ActiveWindow.SelectedSheets`)를 알려 주는 조회. 지금 `sheets` 조회에는 없다.
- 주의: **원클릭 백업**은 "저장 안 한 변경까지 포함한 복사본"이라 `SaveCopyAs`처럼 엑셀이 직접 해야 하는 일이다. 훈수꾼이 파일 탐색기식 복사를 하면 마지막 저장본만 복사돼 의미가 달라진다. 입력 칸 비우기는 되돌릴 수 없으므로 확인 창이 필수.

| 마지막 셀 바로잡기 `BookClean_FixLastCell` | 서식만 남은 빈 구역을 지워 Ctrl+End·파일 크기 정상화(보호·표·도형 있는 시트는 건너뜀) | `hunsu-sheetinfo`(사용 범위 크기): 사용 범위가 실제 데이터보다 크면 **[바로잡기] 단추** |
| 외부 링크·깨진 이름 정리 `BookClean_Links` | 다른 파일 링크를 값으로 굳히고 끊기, `#REF!` 이름 삭제 | **`hunsu-links`(외부 링크 목록), `hunsu-names`(이름 목록), `hunsu-audit`가 이미 문제를 "보여 준다"**. 빠진 건 "고치기" 쪽뿐 |
| 인쇄 설정 일괄 복사 `BookClean_CopyPage` | 현재 시트의 용지·방향·여백·배율·머리글/바닥글을 다른 시트에 복사 | 없음. `PageSetup`은 엑셀 안에서도 느린 호출이라 다리 VBA 명령 권장 |

### 3-9. `visible-copy` 보이는 칸만 복사·붙여넣기: **C (엑셀에 남김)**
- 하는 일: 필터·숨긴 줄이 있는 표에서 ① 보이는 칸만 복사 ② 목적지의 **보이는 줄·열에만** 차례로 붙여넣기(숨은 곳은 건드리지 않음).
- 남기는 이유: 엑셀 클립보드(`CutCopyMode`)와 붙여넣기 동작에 끼어드는 도구이고 진입이 우클릭 메뉴·`OnKey`다. 훈수꾼의 단축키는 호출·숨김 두 개로 정해져 있고(사용자 결정), 엑셀 우클릭 메뉴에는 훈수꾼이 항목을 달 수 없다.
- 나중에 정말 옮기려면: 다리에 쓰기 명령 `paste.visible`을 두고 훈수꾼 단추로 부르는 방식이 있으나, "복사 → 붙여넣기" 두 단계를 앱 단추로 하는 건 원래 도구보다 불편해진다. **우선순위 가장 낮음.**

### 3-10. `image-fit` 사진 셀에 맞추기: **C (엑셀에 남김)**
- 하는 일: 사진 파일을 골라 선택 칸에 비율대로 맞춰 넣기 / 클립보드 사진을 붙여넣고 맞추기 / 이미 있는 사진 맞추기(매크로 3개). 기본 단축키 `Ctrl+Shift+A`, `Ctrl+Shift+V`.
- 남기는 이유: **붙여넣기 키(Ctrl+Shift+V)를 엑셀 안에서 가로채는 도구**이고 `Shapes`·클립보드·칸 크기 계산이 한 흐름이다. 훈수꾼의 전역 단축키로 하면 다른 프로그램의 같은 키와 부딪힐 수 있다.
- 이관 가능한 부분: "선택한 사진을 칸에 맞추기"만은 명령(B)으로 뺄 수 있다. 계산 `CoFitMath_CalcBox`는 순수 함수라 C#으로 옮기기 쉽다. 그러나 효용이 작아 권하지 않는다.

### 3-11. 라이브러리 묶음 (추가기능이 아니라 부품)
| 대상 | 분류 | 비고 |
|---|---|---|
| `clockout-lib`(공용 VBA) | **C (남김, 더 키우지 않음)** | 남는 VBA 추가기능이 있는 동안만 의미가 있다. **훈수꾼 다리(`clockout-hunsu`)도 이 라이브러리와 `clockout-vendor-data`에 의존한다**(선언 파일). 그래서 지금 내릴 수 없다 |
| `clockout-vendor-array|data|sys|text` | **C (남김, 새로 받지 않음)** | C#에는 같은 일을 하는 표준 기능이 있다(JSON, 정규식, 컬렉션). VBA 추가기능이 전부 사라지면 같이 정리 |
| `vendor-sample`(JSON 보기 좋게) | **D (폐기 가능)** | 카탈로그에 올라가지 않는 예제 |

## 4. 핵심 설계 결정 (훈수꾼 프로젝트와 사용자가 정할 것)
### 4-1. 쓰기 명령을 허용할 것인가 (가장 큰 결정)
현재: 다리는 읽기와 `goto`/`sheet.activate`만 한다(docs/01 9장 8번, docs/02 1·6장). 옮기려는 B 항목 약 30개는 전부 쓰기다.
- **선택지 가**: 쓰기 명령 신설. 모듈 선언의 `commands`에 쓰기 명령을 적게 하고, `scope`에 쓰기 권한 단계를 더하고(예: `write`), 앱이 **"N칸이 바뀝니다" 확인 창을 공통으로 띄운다**(기존 추가기능이 각자 하던 것을 훈수꾼이 한 곳에서). 되돌릴 수 없음 안내와 "먼저 저장하세요" 문구 포함.
- **선택지 나**: 훈수꾼은 영영 읽기 전용으로 두고, 쓰는 도구는 엑셀 추가기능으로 유지(이관 안 함). 사용자의 방향(추가기능을 키우지 않음)과 어긋나므로 권하지 않는다.
- **칼퇴 쪽 의견**: 가. 이유: 실행 취소 기록 보호가 원칙 8번의 이유인데, 추가기능도 이미 되돌릴 수 없다고 안내하며 쓰고 있어서 훈수꾼이 바깥에서 쓴다고 더 나빠지지 않을 것으로 본다. 오히려 확인 창·한도·오류 처리를 한 곳에 모을 수 있다. 다만 **칼퇴 쪽은 엑셀에서 실행해 보지 못했으니, 바깥 프로세스의 COM 쓰기가 실행 취소 기록에 어떻게 작용하는지는 훈수꾼 쪽에서 실측해 확인해 달라.**

### 4-2. 도구의 "머리"를 어디에 둘 것인가
모듈은 선언형이라 코드를 실행하지 않는다(docs/01 4.1장). 그러나 B 항목은 계산(자연 순서, 한글 금액, 날짜 해석)과 검사(병합·보호·한도)가 있다. 세 길이 있다.
1. **C# Core에 순수 함수로 두고**(`dotnet test`로 시험) 앱이 칸 값을 배열로 한 번에 읽고, 계산하고, 배열로 한 번에 쓴다. 칸 단위 COM 호출을 하지 않는다. 칼퇴 쪽 권장.
2. 다리 VBA에 `CoHunsuDo_<이름>.bas`로 둔다. 엑셀 안에서 도는 장점(속도)이 있으나 **추가기능을 다리 안에 다시 짜는 꼴**이 되고, 코드 중복(VBA lib + 다리)이 생긴다.
3. 섞기: 순회가 필요한 일(색 읽기, `PageSetup`, 파일 저장)은 다리 VBA, 나머지는 C#.
- 기존 VBA의 `Test_CoText`·`Test_CoNum`·`Test_CoFitMath`·`Test_CoKey`에 **시험 값이 이미 들어 있다**. C#으로 옮길 때 그대로 시험 값으로 쓸 수 있다.

### 4-3. 진입점(우클릭 메뉴)을 잃는다
기존 도구는 셀·시트 우클릭이 입구다. 훈수꾼에는 엑셀 우클릭 메뉴에 항목을 다는 길이 없다. 대안: **"도구" 모듈(예: `hunsu-tools`)**에 명령 목록과 검색(`input`)을 두고 호출층(`summon`)으로 부르기. 이때 필요한 부품이 지금 코드에 없다: `ViewSpec.RenderedItems`에 있는 건 stat·text·badge·divider·list·button·bar·spark·progress뿐이고, **`input`·`toggle`·`tabs`와 확인 창, 값을 입력받는 창**(찾아 바꾸기 문구, 단위 고르기, 앞뒤 글자)은 문서에만 있고 그리는 코드는 찾지 못했다. 입력이 필요한 도구가 많다(`SheetMake`, `RoundValues`, `AddAffix`, 이름 일괄 바꾸기).

### 4-4. 설정 이어받기
추가기능 설정은 칼퇴 설정창에 저장된다(`ClockOut_GetSetting(id, key, 기본값)`, `params`). 훈수꾼 모듈 `params`는 "기존과 같은 형식"이라 값 이름(key)을 **그대로 두면** 사용자가 바꿔 둔 설정을 이어받을 수 있다. 이관할 때 key 이름을 바꾸지 말 것.

## 6. 이관 순서 제안 (사용자가 정하는 것, 칼퇴 쪽 추천)
1. **0순위, 코드 없음**: `selection-stats`와 `hunsu-selection`의 규칙 차이 정리 → 맞춘 뒤 카탈로그에서 `selection-stats`를 내릴지는 사용자가 결정.
2. **A 묶음(쓰기 규칙 불필요)**: ① `cross-hair` → 표시층(스크롤 따라가기 검증 포함) ② 폴더 파일 목록 → 패널 ③ 색깔별 합계 → `color.sum` 조회 + 패널 ④ 두 열 다른 칸 → 차이 목록 + `goto`.
3. **쓰기 규칙 결정(4-1)과 확인 창·입력 부품(4-3) 만들기**. 이게 끝나야 B가 시작된다.
4. **B를 "보기 옆 단추"부터**: 책 점검 옆 [숨은 시트 모두 보이기], 외부 링크·이름 옆 [끊기]·[삭제], 사용 범위 옆 [마지막 셀 바로잡기]. 확인 창을 가장 먼저 시험하기 좋은 작은 쓰기들이다.
5. **B의 값 정리 묶음**(`value-tools`, `quick-tools`): C# Core 순수 함수 + 배열 입출력. 한 번에 한 추가기능씩.
6. **마지막**: `range-tools`·`sheet-tools`·`book-tools`의 시트 만들기·쪼개기·내보내기·PDF·백업(엑셀 쪽 파일·시트 조작이라 위험이 큼).
7. **끝까지 남김(C)**: `visible-copy`, `image-fit`, `clockout-lib`, vendor 묶음.
- 추가기능을 내리는 시점은 **훈수꾼 쪽 대응 기능이 PC에서 눈으로 확인된 뒤**에 사용자가 정한다. 그때까지 추가기능은 카탈로그에 그대로 둔다.
